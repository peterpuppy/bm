# 支付商品为何显示"无法购买"

## 结论

**不是代码问题** —— `openPS5Checkout()` 的参数是对的，弹窗能起来（`sceNpCommerceDialogOpen2` 返回 `SCE_OK`）。

**是 PSN 侧判定该 product 不可购买**，因为 DevNet 商品配置 / 认证流程未走完。

---

## 原因

### 1. 这是 CHECKOUT 模式的**预期行为**

> Products to purchase can either be specified using product labels or using product labels and
> SKU labels. **An error occurs if even one already-purchased product or product that cannot be
> purchased is specified.**

来源：<https://game.develop.playstation.net/resources/documents/SDK/12.000/NpCommerceDialog-Overview/using-the-checkout-mode.html>

另一处：

> **Checkout Mode**
> Displays one or multiple products specified as a parameter on the "Purchase Confirmation"
> screen. **An error occurs if there is a product among the products specified that has already
> been purchased or a product that cannot be purchased.**

来源：<https://game.develop.playstation.net/resources/documents/SDK/12.000/NpCommerceDialog-Reference/sce-np-commerce-dialog-mode.html>

**「当前无法购买」是 PS5 系统 UI 的文案**，不是游戏的。

### 2. 商品还有两项未就绪（实际查证）

**In-Game Catalog 里该商品的两列为空**：

```
NAME        TYPE                          ENTITLEMENT ID                            VALID  STATUS  DEV/SP-INT PUBLISH DATE
CONQ COIN   Add-on - Unified Entitlement  HP3255-PPSA38951_00-0683974373790429      (空)   (空)    2026-08-31
```

**Certification Center 的 On Hold（GC-119326），两条原因**：

```
1. Awaiting submission of base application.
   Please contact CertOps via the communications tracker when this has been submitted.

2. This DLC is not appearing on the Regional or title store preview.
   Please verify that the DLC is set up correctly and raise a Help Center ticket
   if assistance is needed.
```

来源：Certification Center → Submission Manager → GC-119326
<https://certify.playstation.net/fqaweb/index.cfm?event=submission_manager.main>

### 3. DLC 认证依赖主程序

`Awaiting submission of base application` 的含义：**DLC 认证要求 base application 先进系统。**

Submission Manager 里**只有 CONQ COIN 一条**，没有主程序 `CONQ (PPSA-38951)` 的记录。

### 4. `DLC` 提交类型是**正确的**，不是配置错误

一度怀疑"内购金币选了 DLC 是选错了"。查 Add-On MDT 指南后**推翻**：

> **The following information is required on a DLC MDT form.**
>
> **Service Entitlement (PlayStation®4 and PlayStation®5 only)**
> This subsection **only appears for DLC set up as a consumable in Content Pipeline**.

来源：<https://learn.playstation.net/bundle/certops-guide/page/mdt_add-on.html>

**SIE 认证体系里，PSVC/PSCONS 这类内购商品统一走 `DLC` 提交类型** ——
`DLC` 是认证术语，涵盖所有 Add-on，不是狭义的"资料片"。

本产品 MDT 表单实测：
```
Product Type:                DLC
Entitlement - Package Type:  PSVC
Content ID:                  HP3255-PPSA38951_00-CONQCOIN00000000
MDT Status:                  FINAL          ← 已提交，必填项齐全
```

### 5. Communication Tracker：一条记录都没有

```
My Communications → [No Communications]
```

**从未联系过 CertOps。** 而 On Hold 两次原文都要求「解决后通过 Communication Tracker 联系 CertOps」
—— 这是**人工放行**流程，不联系就永远挂着。

### 6. 邮件里的 `{0}` 未替换

```
SIE Regions: {0}: SIEA, SIEE, SIEJA_ASIA, SIEJA_JAPAN
Platform:    {0}: PS5
```

**模板变量未渲染**，通常意味某项配置为空。这是 SIE 邮件模板的内部变量，**文档无说明，需问 SIE**。

## 当前卡点（按依赖顺序）

| # | 事项 | 依赖 |
|---|---|---|
| **1** | **Communication Tracker 开沟通** | 无，**先做这个** |
| 2 | 确认主程序 `PPSA-38951` 认证状态（或问能否豁免） | 待 1 的回复 |
| 3 | DevKit 验 Title Store Preview 可见性 | 无 |
| 4 | 等 Availability 2026-09-20 | 无 |

**DEV 与 RETAIL 的差别**：DEV 不需要 SIE 认证审核（Product Preview 直接发），
但 **PAR + Availability 规则不分环境**，**Certification Center 的 On Hold 也仍需解除**。
