R5002 PlayGo - Initial Chunk Set (Initial Payload)

TEST | APP




Premise: If the application is published as a full game product




Requirement: All of the following conditions are satisfied:

The size of the initial chunk set (initial payload) does not exceed 20GiB
Gameplay elements representative of the application are included in the initial payload
When the user attempts to access a mode that is not included in the initial payload, the application does not block game progress or prevent the user going back to the mode selection screen until downloading or data copy from disc completes

Also, the conditions above apply to all combinations of the following PlayGo related features which can be utilized by the application:

Application operation mode mask (when using the optimized installation feature)
Language mask
Scenario mask
Description

Demos and betas are exempt from this requirement.

If the application is split into multiple chunks, even if the initial payload is less than 20 GiB, the application will have to adhere to R5158 regardless of the product type (That is, this applies to full game products, demos and betas).

Plan your application with this requirement in mind from the initial stage of your game development. Restructuring of data to fit within the initial payload at later stages of development may cause issues that require significant resources to resolve.

The PlayGo system enables applications to run without the entire application package being installed. The set of chunks required for starting the application and playing for a certain amount of time is called the "initial chunk set (initial payload)". The system software will not start the application until the initial payload is downloaded/installed to the storage.

The size of the initial payload will determine how long the user will have to wait before being able to start the application. Utilise application operation mode mask, language mask and scenario mask to reduce the size of the initial payload and only include content significant for the user. By using the optimized installation feature, it is possible to configure chunks for each application operation mode. For details about application operation modes, please refer to "Programming Startup Guide - Basic Information on Application Execution Environments - Application Operation Modes."

The expectation is that the duration of the mode provided in the initial payload covers approximately one hour. It is acceptable to provide activities that are designed to be replayable (for example, certain race track or football matches that can be played repeatedly).

If a mode outside of the initial payload is selectable before it has been downloaded/copied, you should mark such mode to the user to signify that it is not yet available. For example, you could gray out a mode in a menu or display a message about an area not yet ready (such as, "Please wait until the download/copy is complete: xx minutes").

The purpose of this requirement is that users can play the game as soon as possible. However, if complying with this requirement would impair the game design or user experience, SIE may allow the initial payload size to be larger than the size specified by the requirement. For example,

When trying to reduce the size of the initial payload by using application operation mode mask, language mask and scenario mask, etc., but cannot provide the intended user experience within the specified size
When the quality of the game is degraded by lowering the resolution of the assets used in the start scene of gameplay to comply with this requirement

If one of the above applies to the application, contact Private Support via the PlayStation®5 Developer Network website ( https://game.develop.playstation.net/ ) with the below:

Required size of the initial payload
Reason for requiring that size
Full package size
Does the application have at least one of the following?
Open world (The players can approach objectives freely and access assets)
Online multiplayer only
(if 4 is no) Does the application use the scenario mask? If not, why
(if 4 is no) Does the application have language-specific data? If yes, below:
Total file size for each language (e.g. common: 30GiB, English: 8GiB, Japanese: 12GiB)
Is the language mask set for those chunks? If not, why

R5158 PlayGo - Download Test per Language/Scenario

TEST | APP




Premise: If the application is split into multiple chunks




Requirement: Even while being downloaded and installed, it must not freeze or become unresponsive, including cases where the user attempts to access chunks that have not yet been installed.

In addition, if the following are defined in the PlayGo chunks, the above conditions are also satisfied for all combinations:

Application operation mode mask (when using the optimized installation feature)
Language mask
Scenario mask
Description

The PlayGo system enables applications to run without the entire application package being installed. This is achieved by breaking the application into multiple "chunks".

The selection of chunks installed depends on whether:

the application supports the optimized installation feature
Chunks are defined according to the application's operating modes.
the application supports multiple scenarios
It is possible for users to delete unwanted scenarios and/or languages associated chunks
Language options are set to chunks
Only chunks with the language option set in the system language setting will be downloaded/copied
the application has chunks outside of the Initial Chunk Set (Initial Payload)

If the user changes the system language after starting the download/copy of the application, the system software will not automatically download/copy the language chunks for the new language. However, the user can manually add/delete language/scenarios via a system UI. Additionally, the application can download/copy chunks for different languages and scenarios by using the PlayGoDialog library. Make sure that the correct assets are associated with the language options chunks used by the application.

When a previously installed application is being reinstalled or if one or more scenarios were deleted, the user may attempt to load save data that requires chunks no longer installed.

Under these circumstances it is acceptable to prevent the user from loading the save data but the application should at least inform the user when loading is not possible.

R5198 PlayStation®5 Pro - Feature Parity

TEST | APP




Premise: -




Requirement:The application must provide the same features in both Trinity mode and Base mode.

If the application supports low energy mode, the same features must be provided in low energy mode as well.

Description

From a content perspective, PlayStation®5 Pro console and the Standard PlayStation®5 console should appear compatible to the user. The purpose of this requirement is to create parity between Trinity mode and Base mode. Visual enhancements in Trinity mode are acceptable throughout the application. Reduction in visual fidelity or performance is acceptable in low energy mode compared to Base mode, as long as the overall quality of the gameplay experience is not compromised.

The following are examples of acceptable/prohibited differences in Trinity mode and Low Energy Mode:

Acceptable differences in Trinity mode relative to Base mode:

Higher frame rate.
More stable framerate.
Richer visual effects (for example,. more particles or bigger crowds).
Ray tracing support.

Acceptable differences in low energy mode relative to Base mode:

Lower frame rate.
Less stable framerate.
Lighter visual effects (for example,. less particles or smaller crowds).

Prohibited differences differences between Trinity mode, Base mode and Low Energy mode:

Game modes and/or online sessions exclusive.
Different numbers of players are permitted to join online sessions.
Different numbers of players are permitted to play in the offline mode.
Additional exclusive features (for example, level editor or multiplayer in the split-screen mode.).
Different playable characters or game resources (for example,. items).
Different game content (for example, additional stages).
Different trophies and trophy-unlocking conditions.
More usable peripherals.
PlayStation®VR2 does not work in low energy mode. Thus, it is not an issue if certain modes that support PlayStation®VR2 are unavailable in low energy mode.

R5197 ContentSearch Library - Requirement When Supporting 8K Output

TEST | APP




Premise: If the application supports 8K rendering and the ContentSearch library is used to handle still images




Requirement:

The following data formats for still images are supported depending on the operation mode of the application:

In Base mode, images with a resolution of 3840x2160 pixels are supported.
In Trinity mode, images with a resolution of both 3840x2160 and 7680x4320 pixels are supported.

However, still images stored by the application with the ContentExport library are excluded from this requirement.

Description

The data format of still images that can be accessed with the ContentSearch library changes according to the operation mode of the application, as well as the system state. Applications must appropriately support still image data even if the accessible format changes.

For example, in applications that support 8K output running in Trinity mode with a feature to display images stored in the internal storage of a PlayStation®5 console using the ContentSearch library, it is a violation of this requirement to have specifications where images with a resolution of 7680x4320 pixels are not displayed.

Regardless of the operation mode of the application, even if the application only stores the images with a resolution of 512x512 pixels with the ContentExport library, and only handles the images with this resolution with the ContentSearch library, it is not a violation.

In addition to the required resolutions for ContentSearch as detailed above, it is no issue to also support images with other resolutions.

R5089 Appropriate Implementation for Suspend/Resume feature

TEST | APP




Premise: -




Requirement: The application is implemented as follows:

The application periodically calls the sce::Agc::suspendPoint() function (hereinafter, suspendPoint()) during usage of the GPU.
After suspendPoint() execution, all the graphics pipe processing completes within 200 msec and the GPU enters a state where the graphics pipe stops running (the GFX IDLE state).
The following functions are not called in a thread where a suspendPoint() will be called.
sceSaveDataPrepare()
sceSaveDataDelete()
sceSaveDataDirNameSearch()
sceSaveDataSetupSaveDataMemory2()
sceSaveDataGetSaveDataMemory2()
sceSaveDataSetSaveDataMemory2()
Description

In order for the system to suspend an application, the GFX IDLE state is required. Have the application periodically call the suspendPoint() at the unit that the call completes of serial sce::Agc::submitGraphics() function so that it is in the GFX IDLE state at regular intervals.

When suspendPoint() and SaveData library APIs written in the above requirement section are called in the same thread, the suspendPoint() may not be called depending on the timing. Thus those APIs must always be called in a thread separated from the thread calling suspendPoint().

TEST | APP




Premise: -




Requirement: When sending video/images/streaming from an application to a Web service, the following conditions are satisfied:

Using the Share library to open the Share menu, the following conditions are met:
The application provides a button clearly associated with the "Share" functionality (see Description).

An icon that approximates the look of the "Share" icon

"△ button: Share"

Uploading images/video to servers operated by publishers

Exporting images/video to the system software
Uploading images/video to PlayStation™Network servers using the Title Cloud Storage or Leaderboards Web API, etc.

R5021 Save Data - Online Storage Support

TEST | APP ADD-ON




Premise: If the application supports reading or writing of saved data.




Requirement: The application reads/writes saved data correctly. Particularly, in order to ensure that save data is appropriately backed up to online storage, the application runs correctly regardless of the model type.

Description

Note that the "save data" referred to in this requirement is generally focused on the application's progress information data. Data such as settings data (for example, in-game brightness, audio volume, and sub-titles) is excluded from this requirement.

This requirement is for checking that save processing has been correctly carried out when a save operation is performed within the application. After the completion of the save operation, terminate and then start up the application again and load the saved data to check whether the progress of the application at the time of the save is correctly loaded.

The application must run correctly when save data uploaded to online storage is downloaded to both the original PlayStation®5 console and another PlayStation®5 console, regardless of model type. Take care to avoid the following problems when designing and implementing the application:

When information dependent on a specific machine is included in the save data, save data copied to another PlayStation®5 console via online storage will become unusable.
When information associated with save data (information representing game progress) is saved to temporary data areas or download data areas, the save data by itself will become unusable because temporary data areas and download data areas cannot be copied to online storage.

The user ID used for obtaining data of the wireless controller and for operating save data is a local ID assigned within the PlayStation®5 console. Even if user ID information is included in save data backed up to online storage, that user ID cannot be used on another PlayStation®5 console; do not link save data to a certain user ID. For example, using a user ID for a directory name would be a violation of this requirement.

R5096 Error Handling in Saving/Loading Save Data, Images, and Videos

TEST | APP




Premise: If any of the following applies:

The SaveData library is used (however, this does not apply if only save data memory is used)
The ContentExport library is used
The Share library is used to create screenshots and video clips



Requirement:

If the SaveData library is used and there is insufficient space, the user is not required to restart the application and is allowed to retry the saving process.

If failing to export/read the image or video, the application does not freeze or become inoperable.

Description

Regarding this requirement, it is not required to display a message to the user. If a message is displayed, the content of the message is at the discretion of the application.

SaveData library

This requirement is to prevent save data (or progress) from being lost.

sceSaveDataMount3() will return SCE_SAVE_DATA_ERROR_NO_SPACE_FS when attempting to create save data when there is insufficient storage space.

Whether it is an auto-save or a manual save by the user, if the save fails due to insufficient storage space, please provide an opportunity to save again without losing progress. Saving must not be disabled throughout the application. It is acceptable to either implement a mechanism that halts game progress until the save is successful or to attempt saving again at the next save point.

ContentExport library

The sceContentExportFrom* API will return SCE_CONTENT_EXPORT_ERROR_DISKFULL when attempting to export when there is insufficient storage space. Additionally, do not implement the application assuming that the path to the exported content can be accessed.

Share library

sceShareCaptureScreenshot() and sceShareCaptureVideoClip() will return SCE_SHARE_LIBRARY_ERROR_NO_SPACE when attempting to create screenshots / video clips when there is insufficient storage space.

R5076 Share & Remote Play - Prohibited Section Configuration

TEST | APP




Premise: If setting a prohibited section in any of the following features:

Remote play
The following share-related features:
Video clip recording
Live streaming broadcast
Share play



Requirement:

Remote play

The prohibited sections are limited to scenes that require cameras/peripheral devices.

Video clip recording / Live streaming broadcast / Share play

The prohibited section is not the entire application.
Description

"Remote play" is a feature that allows the same user to operate the PlayStation®5 console from a game console, PC, or mobile device. The Share feature is one of the efforts undertaken with the goal of helping user content reach a broader audience beyond the PlayStation™Network. As each feature has a different purpose, the prohibited sections are different.

Remote play and all share related features are permitted by default. Applications can use the Share library to manually prohibit remote play and share related features in specific sections.

Remote play

If cameras/peripherals are required for the entirety of gameplay, then it’s acceptable to block remote play as soon as the application starts.

Please refer to Remoteplay Library Overview for remote play limitations. If these limitations conflict with the application's operation, then users should be made aware of this through the application's official website or store metadata. Remote play must not be prohibited due to these limitations.

Share-related features

When setting a prohibited section it is recommended that the prohibited section be as short as possible. It is not allowed to set the entire application as a prohibited section. For example, it is recommended that the application set prohibited sections only for specific scenes that:

have spoilers
include items (e.g. musical piece) whose distribution is not permitted by copyrights
contain information such as personal information that should remain confidential
