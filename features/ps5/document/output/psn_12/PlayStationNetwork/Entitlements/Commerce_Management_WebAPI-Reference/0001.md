# Commerce Management Web API Reference Summary

The Commerce Management Web API allows you to retrieve events from self-defined title streams. A title stream is associated with one or more game titles and each title stream can have multiple event streams. You can retrieve all events from a specific start position.

After onboarding, an SIE Admin will provide you with the partnerName to be used in Web API requests.

**Supported Event Types**

The Commerce Management Web API supports two event domains:

* PAYMENTS - Includes REFUND, CHARGEBACK, and CHARGEBACK REVERSAL events from payment transactions.
* SUBSCRIPTION - Includes subscription lifecycle events (e.g., AUTO\_RENEW\_ON, AUTO\_RENEW\_OFF).

**Streams**

A stream refers to a container in which events are kept. There are three types of streams:

* Partner level stream - All events related to a partner are captured under this stream. This stream is created by the system during partner creation.
* Title level stream - All events matched to one or more Title IDs are in this stream. Title level streams are created by you, and you can have one stream per game title or streams that group events for multiple game titles. events are kept in the stream in the same order they arrived. You can access events at any time by their position. Use [getStreamListInDetailV3](0001.html#getstreamlistindetailv3) to get a valid start position for each stream while reading events.
* Event level stream - You can configure streams for specific event types, for example, REFUND, CHARGEBACK, CHARGEBACK REVERSAL, and SUBSCRIPTION. Event level streams are created by the system during title level stream creation.

**Creating Streams**

Once onboarding is complete, you can start creating title streams. Streams do not receive any events until you add Title IDs to the stream. Additionally, for the SUBSCRIPTION event type, a notificationUrl must also be registered. If you decide not to create a customized stream, the root partner level stream contains all of the Title IDs which you can use to pull event data from.

Add Title IDs to a stream to capture events relevant to the title in the title stream. You can only add Title IDs for game titles that belong to you, meaning the Client ID you use must have access to the Title ID.

If you delete Title IDs from the stream, events related to the Title ID are not captured in the stream.

You can also retrieve a list of available streams. [getStreamListInDetailV3](0001.html#getstreamlistindetailv3) exposes metadata for SUBSCRIPTION event type streams. For example, the notification URL.

**Event Retention**

Events in the stream are deleted after three years and one day from the time they are made available in the API. Both [getStreamEvents](0001.html#getstreamevents) and [getStreamEventsV2](0001.html#getstreameventsv2) throw errors if the start position provided is less than the valid start position obtained in [getStreamListInDetailV3](0001.html#getstreamlistindetailv3). Use [getStreamListInDetailV3](0001.html#getstreamlistindetailv3) to get a valid start position for the stream.

**Historical Event Retrieval**

[getStreamEventsV2](0001.html#getstreameventsv2) supports historical event retrieval using date range filtering. This is only valid for event level streams. This allows you to query events within a specific time period using the start and end query parameters.

Key features:

* Filter events by creation date range (ISO 8601 format)
* Cursor-based pagination using nextPageToken for efficient large result set handling
* Maximum 500 events per request (controlled by fetchSize)
* When hasMore is true, use the returned nextPageToken in subsequent requests

Example:

```
?start=2025-08-01T00:00:00Z&end=2025-08-02T00:00:00Z&fetchSize=100
```

**Call Rate Limits**

It is recommended that the call rates for the Commerce Management Web API are kept within the following ranges. Note that there is a possibility of rate limits changing without notice. Use the following information as a reference only.

| Request | Recommended Call Rate |
| --- | --- |
| getStreamList | Within 10 times / 5 minutes |
| getStreamListInDetail | Within 10 times / 5 minutes |
| getStreamListInDetailV2 | Within 10 times / 5 minutes |
| getStreamListInDetailV3 | Within 10 times / 5 minutes |
| getStreamEvents | Within 10 times / 5 minutes |
| getStreamEventsV2 | Within 10 times / 5 minutes |
| postStreamEventFeedback | Within 100 times / 1 minute |

### Base URLs

### Application Servers or Back Office Servers

The base URL to specify for application servers and back office servers depends on whether the client-side application uses the Sandbox network architecture or Legacy network architecture.  
(Refer to [Sandbox Network Architecture Guide](../../../SDK/latest/Sandbox_Network_Architecture-Guide/__document_toc.html) for details about Sandbox. Also refer to this technote regarding migration to Sandbox: <https://game.develop.playstation.net/technotes/view/740>. )

Specify the following base URL if the client-side application uses Sandbox:

* https://s2s.np.playstation.net/api/partnerEventService

Specify the base URL of the applicable environment indicated below if the client-side application uses Legacy:

* Development environment (sp-int): https://s2s.sp-int.playstation.net/api/partnerEventService
* Certification environment (prod-qa): https://s2s.prod-qa.playstation.net/api/partnerEventService
* Production environment (RETAIL): https://s2s.np.playstation.net/api/partnerEventService

For the purpose of maintaining backward compatibility, the above base URLs for Legacy can also be specified for application servers and back office servers that have migrated to Sandbox. For application servers and back office servers that serve traffic in both the Sandbox and Legacy network architectures, specify the base URL for Sandbox regarding Sandbox requests and specify the base URLs for Legacy regarding Legacy requests.
