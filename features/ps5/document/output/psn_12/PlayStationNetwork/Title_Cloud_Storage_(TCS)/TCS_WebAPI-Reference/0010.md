# uploadData

Write TCS data

### Description

This request writes TCS data to a slot owned by the specified user. If the specified user is anyone, the write destination will be a slot owned by the title.

For the procedures for linking supplementary data to TCS data, refer to the description of [setDataInfo](0010.html).

If an account ID has been specified for *X-Psn-Tcs-Compared-Last-Updated-User-Account-Id* and a time has been specified for *X-Psn-Tcs-Compared-Last-Updated-Date-Time*, a conditional write can be performed, as with TCS variables. For *X-Psn-Tcs-Compared-Last-Updated-User-Account-Id* and *X-Psn-Tcs-Compared-Last-Updated-Date-Time*, processing is not executed, and an error occurs, if no TCS data has been registered to the slot. Use *X-Psn-Tcs-If-Slot-State* to perform a conditional write to slot to which TCS data has not been registered. If empty is specified for *X-Psn-Tcs-If-Slot-State*, processing is executed only if no TCS data has been registered to the slot. *X-Psn-Tcs-Compared-Last-Updated-User-Account-Id* or *X-Psn-Tcs-Compared-Last-Updated-Date-Time* cannot be specified simultaneously with *X-Psn-Tcs-If-Slot-State*.

**Example Request**

```
PUT titleCloudStorageBaseUrl/v1/apps/myApp/users/1234567890/data/slots/0

XXXXXXXXXXXXXXXXX(binary data)
```

**Example Response**

```
{
  "objectId": "9607a6e0-57c8-4cdb-9728-187da6cd25d7"
}
```

# downloadData

Read TCS data

### Description

This request reads TCS data from a slot owned by the specified user. If the specified user is anyone, the read source will be a slot owned by the title.

It is also possible to obtain a TCS data status beforehand, and specify the object ID obtained then with the request described in this section to obtain TCS data and its status atomically.

Using the split download feature, it is also possible to download TCS data in parallel or sequentially across multiple requests. To do so, specify Range (e.g., Range: bytes=0-1024) in the request header. If the split download is executed successfully, the downloaded data range and the overall data size will be notified in the response header Content-Range (e.g., Content-Range: bytes 0-1023/10240: bytes 0-1023/10240).

**Example Request**

```
GET titleCloudStorageBaseUrl/v1/apps/myApp/users/1234567890/data/slots/0
```

**Example Response**

```
Last-Modified: Thu, 10 Jan 2019 20:42:56 GMT
Content-Length: 4649
ETag: "bcc80b8d-aa25-4cc3-be44-682b06f9110c"

XXXXXXXXXXXXXXXXX (binary data)
```

# setDataInfo

Write supplementary data for TCS data

### Description

This request writes supplementary data for TCS data to a slot owned by the specified user. If the specified user is anyone, the write destination will be a slot owned by the title.

With the following procedures, you can link and upload TCS data and supplementary data.

1. When uploading supplementary data, specify X-Psn-Atomic-Operation: begin in the request header for the request described in this section.  
   As a result, X-Psn-Atomic-Operation-Id: {UUID} will be obtained in the response header.
2. Specify the X-Psn-Atomic-Operation-Id obtained in step 1 and X-Psn-Atomic-Operation: end in the request header, and call [uploadData](0008.html).

As shown below, the link can be made in the opposite order.

1. When uploading TCS data, specify X-Psn-Atomic-Operation: begin in the request header for [uploadData](0008.html).  
   As a result, X-Psn-Atomic-Operation-Id: {UUID} will be obtained in the response header.
2. Specify the X-Psn-Atomic-Operation-Id obtained in step 1 and X-Psn-Atomic-Operation: end in the request header, and call the request described in this section.

**Example Request**

```
PUT titleCloudStorageBaseUrl/v1/apps/myApp/users/1234567890/data/slots/0/info

{
  "info": "c3VwcGxlbWVudGFyeSBpbmZv"
}
```

HTTP status 204 will be returned when the above request example succeeds. There will be no response body.

# deleteMultiDataBySlot

Delete TCS data from multiple users

### Description

You can specify one slot ID and multiple account IDs and delete the TCS data owned by the users indicated by the IDs all at once. The maximum number of account IDs that can be specified at once is 32. Specifying a number of IDs outside that range will result in an error. Additionally, anyone cannot be specified at the same time as ordinary account IDs or me. If you would like to delete TCS data from a slot owned by the title, specify anyone only.

If multiple account IDs are specified, there will be an error if even a single deletion fails. If this happens, then it is possible that other TCS data has been successfully deleted. If processing for deletion is performed on an already deleted or non-existent slot, there will be no error. Therefore, if an error is returned, it is not a problem to re-run the request without changing specifications.

**Example Request**

```
DELETE titleCloudStorageBaseUrl/v1/apps/myApp/users/data/slots/0?accountIds=1234567890,2345678901
```

HTTP status 204 will be returned when the above request example succeeds. There will be no response body.

# deleteMultiDataByUser

Delete TCS data from multiple slots belonging to the specified user

### Description

This request deletes TCS data from a slot owned by the specified user. If the specified user is anyone, deletions will be made from slots owned by the title.

The maximum number of slot IDs that can be specified at once is 128. Specifying a number of slots above that limit will result in an error. If multiple slot IDs are specified, there will be an error if even a single deletion fails. If this happens, then it is possible that other TCS data has been successfully deleted. If processing for deletion is performed on an already deleted or non-existent slot, there will be no error. Therefore, if an error is returned, it is not a problem to re-run the request without changing slot specifications.

If an account ID is specified for *X-Psn-Tcs-Compared-Last-Updated-User-Account-Id* and a timestamp is specified for *X-Psn-Tcs-Compared-Last-Updated-Date-Time*, these will be compared with the latest updater and latest update date and time, respectively, that are recorded for the slot, and deletion will be performed only if these values are equal. If the values are different, an error is error will be returned, and deletion will not be performed. When using this feature, a maximum of 1 slot ID can be specified. Specifying a number of slots above that limit will result in an error. This feature is intended to be used for mutual exclusion, such as when multiple users operate on the same slot and you only want to reflect the operations of the first user.

**Example Request**

```
DELETE titleCloudStorageBaseUrl/v1/apps/myApp/users/1234567890/data?slotIds=0,1,3
```

HTTP status 204 will be returned when the above request example succeeds. There will be no response body.
