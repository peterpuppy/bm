# uploadData

Write TCS data

### Description

This request writes TCS data to a slot owned by the specified user. If anyone is specified, this request writes TCS data to a slot owned by the title.

**Example Request**

```
PUT titleCloudStorageBaseUrl/v1/apps/myApp/users/1234567890/data/slots/0

XXXXXXXXXXXXXXXXX(binary data)
```

**Example Response**

```
{
  "objectId": "9607a6e0-57c8-4cdb-9728-187da6cd25d7"
}
```

# downloadData

Read TCS data

### Description

This request reads TCS data from a slot owned by the specified user. If anyone is specified, this request reads TCS data from a slot owned by the title.

It is possible to obtain data and statuses atomically by obtaining TCS data and its status beforehand and specifying the object ID obtained at the time.

It is also possible to use the split download feature to download data in parallel or sequentially over multiple requests. In such cases, specify Range (e.g., Range: bytes=0-1024) in the request header. If the split download is executed successfully, information concerning the downloaded data range and the overall data size will be notified in the response header Content-Range (e.g., Content-Range: bytes 0-1023/10240).

**Example Request**

```
GET titleCloudStorageBaseUrl/v1/apps/myApp/users/1234567890/data/slots/0
```

**Example Response**

```
Last-Modified: Thu, 10 Jan 2019 20:42:56 GMT
Content-Length: 4649
ETag: "bcc80b8d-aa25-4cc3-be44-682b06f9110c"

XXXXXXXXXXXXXXXXX (binary data)
```

# setDataInfo

Write supplementary data for TCS data

### Description

This request writes supplementary data for TCS data to a slot owned by the specified user. If the specified user is anyone, the write destination will be a slot owned by the title.

With the following procedures, you can link and upload TCS data and supplementary data.

1. When uploading supplementary data, specify X-Psn-Atomic-Operation: begin in the request header for the request described in this section.  
   As a result, X-Psn-Atomic-Operation-Id: {UUID} will be obtained in the response header.
2. Specify the X-Psn-Atomic-Operation-Id obtained in step 1 and X-Psn-Atomic-Operation: end in the request header, and call [uploadData](0005.html).

As shown below, the link can be made in the opposite order.

1. When uploading TCS data, specify X-Psn-Atomic-Operation: begin in the request header for [uploadData](0005.html).  
   As a result, X-Psn-Atomic-Operation-Id: {UUID} will be obtained in the response header.
2. Specify the X-Psn-Atomic-Operation-Id obtained in step 1 and X-Psn-Atomic-Operation: end in the request header, and call the request described in this section.

**Example Request**

```
PUT titleCloudStorageBaseUrl/v1/apps/myApp/users/1234567890/data/slots/0/info

{
  "info": "c3VwcGxlbWVudGFyeSBpbmZv"
}
```

HTTP status 204 will be returned when the above request example succeeds. There will be no response body.

# deleteMultiDataByUser

Delete TCS data from the specified user

### Description

This request deletes TCS data from a slot owned by the specified user. If anyone is specified, this request deletes TCS data from a slot owned by the title.

TCS data can be deleted from a maximum of 128 slots at once. Specifying a number of slots above that limit will result in an error.

If multiple slots are specified, an error will occur if even one deletion fails. If this happens, deletion from other slots may have succeeded. No error will occur if an attempt is made to delete from a slot whose content has already been deleted or that does not exist. Therefore, it is not a problem to re-run the request without changing the specified slots if an error is returned.

**Example Request**

```
DELETE titleCloudStorageBaseUrl/v1/apps/myApp/users/1234567890/data?slotIds=0,1,3
```

HTTP status 204 will be returned when the above request example succeeds. There will be no response body.

# getMultiDataStatusesByUser

Read the TCS data status of the specified user

### Description

This request reads TCS data status about a slot owned by the specified user. If anyone is specified, this request reads TCS data status about a slot owned by the title.

The status fields to obtain can be specified.

A maximum of 32 slots can be specified at once. By default, the results that have been read are sorted in ascending order by slot ID. It is also possible to specify the last update date or the data size as the sorting condition. If multiple slots are specified, an error will occur if even one read operation fails.

An error will not occur if a slot that hasn't been configured yet or a slot that has been deleted is specified, but that slot won't be included in the response. If all the specified slots have not been configured yet or have been deleted, an empty response will be returned.

**Example Request**

```
GET titleCloudStorageBaseUrl/v1/apps/myApp/users/1234567890/data/slots/status?slotIds=0,1
```
