# Boards

# getBoardDefinition

Obtain scoreboard data

### Description

This request obtains data such as the sorting order and the score update mode about the leaderboard specified with *boardId*. Specify the elements to obtain with *fields*. If nothing is specified for *fields*, all elements will be obtained.

**Example Request**

```
GET leaderboardsBaseUrl/v1/apps/myApp/boards/1/definition?fields=entryLimit,updateMode"
```

**Example Response**

```
{
  "entryLimit": 1000,
  "updateMode": "update_with_best_score"
}
```

**Example Request**

```
GET leaderboardsBaseUrl/v1/apps/myApp/boards/1/definition"
```

**Example Response**

```
{
  "entryLimit": 1000,
  "updateMode": "update_with_best_score",
  "sortMode": "desc",
  "largeDataNumLimit": 10,
  "largeDataSizeLimit": 10485760,
  "maxScoreLimit": 100,
  "minScoreLimit": 0
}
```

### Request

```
GET /v1/apps/myApp/boards/{boardId}/definition
```

### URI Parameters

| Name | Type | Required | Description |
| --- | --- | --- | --- |
| boardId | **integer(int32)** | true | Leaderboard ID  **Min Value:** 0 |

### Query Parameters

| Name | Type | Required | Description |
| --- | --- | --- | --- |
| fields | **string** | false | These are the components of the leaderboard specification; the following components can be specified: the value for the maximum number of entries that can recorded on a board (*entryLimit*), the rules for updating scores (*updateMode*), the order in which to sort scores (*sortMode*), the lowest rank at which a player can record large-volume attachment data (*largeDataNumLimit*), the maximum size of large-volume attachment data (*largeDataSizeLimit*), the maximum score value that can be set (*maxScoreLimit*), and the minimum score value that can be set (*minScoreLimit*). These are optional parameters; if specifying multiple parameters, do so separated by commas. |
| npServiceLabel | **integer(int32)** | false | NP service label  **Min Value:** 0  **Default Value:** 0 |

### Status Code 200

### Response Body (getBoardDefinition Response)

**Content-Type:** application/json

| Parameter | Type | Required | Description |
| --- | --- | --- | --- |
| » entryLimit | **integer(int32)** | false | Maximum value for the number of entries that can be recorded on a leaderboard  **Min Value (exclusive):** 0 |
| » largeDataNumLimit | **integer(int32)** | false | The lowest rank (where the player who scored first is ranked higher if there is a tie in terms of points) at which a player can record large-volume attachment data. Only players positioned at this rank or better can record such data.  **Min Value:** 0 |
| » largeDataSizeLimit | **integer(int64)** | false | Maximum size (in bytes) for large-volume attached data  **Min Value:** 0 |
| » maxScoreLimit | **integer(int64)** | false | Maximum score value that can be set |
| » minScoreLimit | **integer(int64)** | false | Minimum score value that can be set |
| » sortMode | **string** | false | Score sorting order. asc is ascending (scores are displayed higher-up the smaller they are), and desc is descending (scores are displayed higher-up the larger they are).  **Possible Values:**  - asc  - desc |
| » updateMode | **string** | false | Score update rules. update\_with\_best\_score means that a player's score can only be updated when it is his or her personal best, and update\_always means that scores can always be updated.  **Possible Values:**  - update\_with\_best\_score  - update\_always |
