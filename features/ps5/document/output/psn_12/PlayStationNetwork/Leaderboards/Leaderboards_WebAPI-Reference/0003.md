# Record

# recordScore

Records scores

### Description

This request records the current user's score on the leaderboard specified with *boardId*. Optionally, a comment (*comment*) and small-volume attached data (*smallData*) can be recorded along with the score. If the *updateMode* setting of a leaderboard is "only overwrite when there is a new high-score" (update\_with\_best\_score), the user's score will not be recorded if it's not a personal best and an error will be returned. By setting *needsTmpRank*=true, the temporary ranking (*tmpRank* and *tmpSerialRank*) can be received as the response. To decrease server load, if there is no need to obtain the temporary ranking, do not specify *needsTmpRank*.

Specifying a date/time in *comparedDateTime* means that for conflict prevention, the specified date/time is compared with the date/time of scores recorded on the leaderboard, and the new score is only recorded if the dates are the same or if the leaderboard scores are older. If the leaderboard scores are newer, the score is not recorded and an error is returned. For information about how to obtain the date and time of recorded scores, refer to the description of [getRanking](0005.html).

Temporary rankings are rankings that can be easily tabulated and should not be revealed to other users. The official ranking will be lower than the temporary ranking if another user records a higher score before the official rankings are calculated. If a large number of users record higher scores and exceed the entry limit (*entryLimit*) that is set for each leaderboard, their scores may be deleted from the rankings before the official ranking can be released. However, if the *updateMode* settings of the leaderboard are "Update Always" (update\_always), a higher-ranking player might record a worse score and go down in the rankings; therefore, it is possible that a player's official ranking will be higher than his or her temporary ranking. Discrepancies between official rankings and temporary rankings like those mentioned above arise because of time lags until the official rankings are calculated. The time lag before an official ranking is calculated is typically a few seconds to a few dozen seconds, at most, but may take up to around 15 minutes, depending on the circumstances. Obtain the official ranking that can be released to other users separately using [getRanking](0005.html).

There will be no error at the moment a score is recorded, even if the temporary ranking exceeds the record limit for the leaderboard. Therefore, rankings exceeding the record limit may be returned by *tmpRank*/*tmpSerialRank*. When the official rankings are calculated on the server, scores in excess of the record limit are deleted.

The content of the comment specified upon registering a score will be checked on the server side; if any inappropriate words are included, they will be masked automatically. The official ranking of the score will not be calculated or made public until checking and masking of the comment is complete. Although the official ranking is calculated at the point when any comment has finished being checked and masked, that calculation will be based on the time when the score finished being recorded, not on the time when the comment is finished being checked and masked.

Input for small-volume attached data must be encoded in Base64.

For the procedures for linking and recording large-volume attached data, refer to the description of [recordLargeData](0003.html).

Setting *waitsForData*=true will result in the score being recorded when recording of the large-volume attached data with [recordLargeData](0003.html) has completed. If the transmission of large-volume attached data does not conclude within a certain amount of time, the recording of the score will be canceled. The official ranking is calculated based on the time when the scores finish being recorded, rather than on when large-volume attached data finishes being recorded. By default, *waitsForData* is set to false. In this case, that means that official rankings of scores will be calculated and Specifies true when a temporary ranking is required released to other players without waiting for large-volume attached data to to be recorded.

**If Recording a Score, a Comment, and Small-Volume Attached Data**

Example Request

```
POST leaderboardsBaseUrl/v1/apps/myApp/boards/0/users/me/score

{
  "score": "100",
  "comment": "at a special game event",
  "smallData": "c3BlY2lhbCB0aWNrZXQgd2FzIHVzZWQ="
}
```

HTTP status 204 will be returned when the request example above succeeds. There will be no response body.

**If Obtaining an Atomic Record ID and Temporary Rankings to Be Able to Record Large-Volume Attached Data Later**

Example Request

```
POST leaderboardsBaseUrl/v1/apps/myApp/boards/0/users/me/score
X-Psn-Atomic-Operation: begin
{
  "score": "50",
  "needsTmpRank": true
}
```

Example Response

```
X-Psn-Atomic-Operation-Id: 82ce6912-a5a9-4838-809e-ecf6c930c2b4
{
  "tmpRank": 3,
  "tmpSerialRank": 4
}
```

# recordLargeData

Records large-volume attached data

### Description

This request records large-volume attached data to the score of the current user within the leaderboard specified with *boardId*. Conceivable examples of such data might include screenshots and gameplay videos. Scores for which large-volume attachment data can be recorded are determined by the floor rank at which large-volume attachment data can be recorded (largeDataNumLimit) set for the leaderboard. For example, if largeDataNumLimit=10, places 1–10 can be recorded, and trying to record position 11 will result in an error and HTTP status 400 will be returned.

After a score is recorded with [recordScore](0002.html), the corresponding large-volume attached data is recorded with the request described in this section.

1. When recording a score, specify X-Psn-Atomic-Operation: begin in the request header for [recordScore](0002.html)  
   This will result in receiving X-Psn-Atomic-Operation-Id: {UUID} in the response header.
2. Specify the X-Psn-Atomic-Operation-Id obtained in step 1 and X-Psn-Atomic-Operation: end in the request header, and call the request described in this section

Example Request

```
POST leaderboardsBaseUrl/v1/apps/myApp/boards/0/users/me/largeData
X-Psn-Atomic-Operation: end
X-Psn-Atomic-Operation-Id: 82ce6912-a5a9-4838-809e-ecf6c930c2b4

XXXXXXXXXXXXXXXXX(Binary Data)
```

Example Response

```
{
  "objectId": "046b6c7f-0b8a-43b9-b35d-6489e6daee91"
}
```
