# Trophy Definition

# getTrophyTitleDefinition

Obtains title configuration data for a certain title

### Description

Obtains the metadata and number of trophies set for the trophy set (base game group) of a certain title.

The target title is determined by the access token assigned to the request and the npServiceLabel query parameter. If npServiceLabel is not specified, information about the title with the npServiceLabel: 0 setting will be returned to the trophy2 service for the title resolved from the access token.

trophyTitleName and trophyTitleIconUrl in the response will be returned in the language that best matches the Accept-Language header provided in the request. If Accept-Language is not specified or metadata in the specified language is not configured, metadata will be returned in the default language.

**Signed imageUrl returned in the DEV and CERT environments**

In the development environment (DEV) and certification environment (CERT) of the Sandbox network architecture, a URL with signature information attached for verifying the access privilege is returned in imageUrl included in trophyTitleIcon of the response. The image can be obtained by accessing the signed URL that is returned.

This signature information comprises the following three query parameters:

* x-psn-sb-signature-ver: signature version (currently fixed at 1)
* x-psn-sb-signature: signature body
* x-psn-sb-signature-exp: signature expiration date (UNIX epoch seconds)

Because the signature information is included in the URL, additional authentication information is not required when accessing imageUrl. Do not rewrite the signature information attached to the imageUrl, and access the signed imageUrl as is. If the signature information is rewritten, the signature will become invalid and you will not be able to obtain the image.

The signature has an expiration date, and if you access an expired imageUrl, an HTTP status 403 error will be returned. The same applies if the signature information is invalid; an HTML error page will be returned, but it will not contain a PlayStation™Network error code. Since the 403 error alone is not enough to determine whether the signature is expired or invalid, check the value of x-psn-sb-signature-exp to determine whether the signature is expired.

The signature information attached to imageUrl is newly created every time this request is executed. When the 403 error is returned due to the signature being expired, re-execute this request to obtain the latest signed URL.

When caching, cache according to the max-age value of the Cache-Control header in the response. The max-age value takes into account the signature's expiration date.

Note that signed URLs are only returned in the development environment (DEV) and certification environment (CERT) of the Sandbox network architecture. imageUrl without a signature is returned in the production environment (RETAIL) and the PlayStation® environments (sp-int, prod-qa, and RETAIL) of the Legacy network architecture.

Refer to [Sandbox Network Architecture Guide](../../../SDK/latest/Sandbox_Network_Architecture-Guide/__document_toc.html) for details about Sandbox.

**Example Request**

```
GET trophyBaseUrl/v1/apps/myApp/trophyTitle?npServiceName=trophy2&npServiceLabel=0
Authorization: Bearer 13e3a918-e820-42b3-8f49-c84eac601679
Accept-Language: en-US, ja-JP
```
