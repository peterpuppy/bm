# Using the UDS Management Tool

The Universal Data System Management Tool allows you to define PlayStation™Network
Objects, UDS Events and UDS stats definitions.

The definition generated by the tool
is for validating and processing a UDS Event in the Universal Data System. In addition,
UDS refers to the definition to build experience.

# Accessing the Tool

This topic explains how to access the UDS Management Tool.

The UDS Management Tool is accessed through a link provided in DevNet. The following
conditions are required to launch the UDS Management Tool from DevNet:

* The UDS service is successfully provisioned to a NP Title ID with a NP Communication
  ID.
* The user is a "Viewer", "Owner", or "Editor" title collaborator for the NP Title ID.

DevNet displays a link to launch the UDS Management Tool in the product detail page
for the title. Refer to the [PlayStation™Network Service Setup Guide](../PSN_Service_Setup-Guide/__document_toc.html) for details on how to configure permissions and provision services. Contact your
developer support representative to receive access to DevNet.

If you are required to provide your credentials to access the UDS Management Tool,
you are presented with the UDS Management Tool login page, shown in the following
figure.

Accessing Login Page

Enter your credentials to access the UDS Management Tool. Through "Need help signing in?", you can reset your password, unlock your account or request support.

# Common Navigation Elements

This topic explains the navigation elements of the UDS Management Tool.

The common navigation elements in the UDS Management Tool consists of three sections:

* PlayStation™Partners global header
* Context switcher
* Navigation menu

The PlayStation™Partners global header provides links to launch other PlayStation™Partners
applications to which you have access. The global header also provides access to manage
your own user profile.

The context switcher displays the current context of the UDS Management Tool. It displays
the NP Communication ID and its corresponding metadata. The context switcher enables
users to switch the NP communication id without going back to DevNet. To access the
UDS Management Tool for another context (NP Communication ID), select the down arrow
next to the NP Communication ID name and select the NP Communication ID you wish to
switch to.

The UDS Management Tool has five top-level menu items (**Home**, **Define Data**, **View Data**, **Features**, and **Publishing**). The **Define Data** menu provides access to **Object Definition**, **Event Definition**, **Stats Definition**, and **Metadata** tools while the **View Data** menu provides access to the **Stats Viewer**, **State Viewer**, and **Event Log Viewer** tools. The **Features** menu provides access to the **Trophy Tool** and **Game Help Tool**. The Publishing menu provides access to NP Config Tag Definition, Integrity Check,
and Publishing History. See the following figure for the main page menu.

This chapter describes configuring various types of metadata.

## Accessing the Metadata Configurator Tool

Upon successful login, the UDS Management Tool displays the home page. The home page
contains a quick guide to getting started with the UDS Management Tool and to access
available documents. You can also access the NP Communication ID Metadata Configurator
Tool to configure common information such as NP Communication ID metadata and subcategories
used in PlayStation™Network object definitions. See the following figure for the Metadata
Configurator.

* To access the Metadata Configurator: Click the gear icon next to the NP Communication
  ID context switcher arrow.
* To manage subcategory metadata: Click the Define Data drop-down menu and select **Metadata**.

## Activity Object Metadata

The UDS Management Tool allows users to manage common metadata used during the activity
creation process. Supported editable metadata include:

* Subcategories
* Subcategory Localization

Subcategories are listed in the **Activity Object** tab, shown in the following figure.
You can specify up to 64 subcategories at a time for each NP Communication ID.

List of Subcategories

1. Select **Actions** > **Create Subcategory for Activities** to create a new subcategory.
2. Specify subcategory attributes from **Attributes**.
3. Specify subcategory localization from **Localization**.
4. Click **Create Subcategory** to save the data.

## Tournament Object Metadata

The UDS Management Tool allows you to manage common metadata used when creating tournaments.
Supported editable metadata include:

* Tournament subcategories
* Tournament subcategory localization

Tournament subcategories are listed in the **Tournament Object** tab.
You can specify up to 64 tournament subcategories at a time for each NP Communication ID.

1. Select **Actions** > **Create Subcategory for Tournaments** to create a new tournament subcategory.
2. Specify tournament subcategory attributes from **Attributes**.
3. Specify tournament subcategory localization from **Localization**.
4. Click **Create Tournament Subcategory** to save the data.

Note:

You must provision the Tournament service for the title to access tournament related
features.

## Common Metadata

The UDS Management Tool supports viewing and editing the commonly shared metadata
for NP Communication IDs, shown in the following figure. The metadata configured is
used by all other service configuration tools for the same NP Communication ID. The
supported common metadata values that are editable are:

* Reference Name. Changeable name of the NP Communication ID for quick reference. For
  example, Uncharted 4 Services.
* Image Icon. Icon for the NP Communication ID. Currently supports 50x50 `.png` file.
* Supported Localized Languages. You can set a default language and any additional supported
  system language. For the current version of the SDK, **Default Language** is set to en-US and changeable.
* Default Language. This is the language that your NP Communication ID is seen in and
  is used as a fall back when the data for supported language is not specified.

  Common Metadata

Note:

Not all the metadata may be editable once the UDS entities are promoted to Platform Certification and Operations or Production Environment. For example, you may not be able to change the default
language or remove existing supported languages. This feature is also available in
other service management tools (Leaderboards Tool, for example). Properties set here
are applicable for the NP Communication ID and may have implications on other services
provisioned to the same NP Communication ID.

# Configuring the UDS Data Model

This chapter describes configuring objects, events, and stats.

## Configuring Objects

**User Permissions and Limitations**

If you are a "Viewer" title collaborator, you can view existing UDS object definitions. In order to create,
edit, or delete UDS objects, you must have either "Editor" or "Owner" title collaborator roles.

**View the List of Defined Objects**

You can access the list of defined PlayStation™Network objects using the object definition
list viewer. Select **Define Data > Objects** to access this view. The object definition list viewer shows the following information
for each defined object:

**Activity**

* **Object ID:** Developer defined identifier of the object.
* **Display Name:** Developer defined name of the object.
* **Category:** Developer defined as Progress, Open Ended, Challenge, or Competitive.
* **Available by Default:** If the activity is available by default.
* **Required:** Developer defined as required for completion or not.
* **Publish Status:** Publish status of the object.
* **Lock Status:** Lock Status of the object.

**Zones**

* **Object ID:** Developer defined identifier of the object.
* **Display Name:** Developer defined name of the object that is visible to the user.
* **Zone Image:** Indicates if the zone image is set for the object.
* **Map Image:** Indicates if the map image is set for the object.
* **Publish Status:** Publish status of the object.
* **Lock Status:** Lock Status of the object.

**Mechanics**

* **Object ID:** Developer defined name of the object.
* **Display Name:** Developer defined name that is visible to the user.
* **Image:** Indicates if the image is set for the object.
* **Publish Status:** Publish status of the object.
* **Lock Status:** Lock Status of the object.

**Actors**

* **Object ID:** Developer defined name of the object.
* **Display Name:** Developer defined name that is visible to the user.
* **Image:** Indicates if the actor image is set for the object.
* **Publish Status:** Publish status of the object.
* **Lock Status:** Lock Status of the object.

Selecting a row in the list displays the detailed information for the object. The
object properties displayed depends on the object type. For activity objects, object
details may also contain the list of tasks associated with the activity. UDS supports
a limited number of objects per object type, per service label (NP Communication ID).
These limits are:

* **Activity/Tasks/Subtasks:** 2560 total
* **Mechanic:** 512
* **Zone:** 512
* **Actor:** 512

Refer to [PlayStation™Network Object Reference](psn-object-reference.html "This topic contains PlayStation™Network object names and attribute descriptions.") for properties defined for each object type.

Note:

Object Bulk Import is an asynchronous process. The object list is not accessible while
object bulk import is in progress in the background. A message displays indicating
that import is in progress. List view refreshes automatically upon the process completion.

**Create a New Object**

You can create a new object by selecting the **Actions** button and clicking on **Create New Object** on the object definition list viewer page. This option displays the object definition
creation page. The following steps are required to create a new object:

1. Select the object type. UDS supports creation of activity, mechanic, zone, and actor
   types.
2. Select the activity category if the selected object type is "Activity". UDS supports progress, open ended, competitive, and challenge categories for activities.
3. The tool displays the required and optional properties based on the selected object
   type.
4. Specify the object properties. For the list and definition of object properties, refer
   to [PlayStation™Network Object Reference](psn-object-reference.html "This topic contains PlayStation™Network object names and attribute descriptions.").
5. For activity objects, create child tasks by selecting the **Add Task** button. This is applicable if your game has missions divided into various subtasks.
6. If tasks are divided into multiple subtasks, access **More Options** > **Create Subtasks** from the parent task.  Select **Add Subtask**  to add subtasks.
7. Provide localized strings. Some properties require a localization string. The Localization
   section shows the supported languages and localizable properties. The list of supported
   languages is determined by the "supported language" metadata of the NP Communication ID (refer to the [Configuring Metadata](configuring-metadata.html "This chapter describes configuring various types of metadata.") section).
8. If the currently assigned default language or the list of supported languages require
   updates, select **Update Language(s)** to quickly access the NP Communication ID Metadata Configurator. Refer to the [Configuring Metadata](configuring-metadata.html "This chapter describes configuring various types of metadata.") section for information on how to use the NP Communication ID Metadata Configurator.

**Edit an Existing Object**

You can edit an existing object from the Object Definition List Viewer. Specify the
object to edit by selecting the **more options** icon for the object, then select the **edit** option. This option displays the Object Definition Edit View for the selected object.

The UDS Management Tool supports deep linking to the object edit screen. If you want
to share object information with other users, you can share the URL of the edit page.
The other user can then access the object edit page directly with the shared URL.

Note:

Once a UDS entity is added to NP Config Tag, the entity may be in a Locked or Partially
Unlocked status. Entities in the Locked or Partially Unlocked status have only limited
editable fields.

**Delete an Existing Object**

You can delete an existing object from the object definition list viewer. Specify
the object to delete by selecting the **more options** icon for the object, then selecting the **delete** option.

**Moving, Unlinking, and Deleting Tasks and Subtasks**

Depending on the lock status of the entity, tasks and subtasks can be moved, deleted,
or unlinked from current parents. You can move tasks and subtasks in any lock status
to another parents. However, you can delete only if the lock status is untagged and
unlink only if the lock status is partially unlocked. These functionalities is provided
in the **Tasks and Subtasks** tab in the Activity Edit view. Parents' lock status also affects the ability to move
their children. Tasks and subtasks cannot be assigned to locked parents or removed
from locked parents.

Note:

Currently the task and subtask list view in the user interface does not show the lock
status. When you click on the icon, only available actions are enabled. Disabled actions
have a tool tip explaining why the action is not available for the selected entity.

To move tasks and subtasks to a new parent, select the **more options** icon for the row and select **Link to a Different Activity** (or **Link to a Different Task** for a subtask). In the displayed modal window, add additional tasks or subtasks if
desired and select the target parent. You are asked to confirm before finalizing the
action.

Task List View
Adding Additional Tasks and Selecting Target Parent

To unlink tasks and subtasks, select **more options** icon for the target row and select **Unlink from Activity** (**Unlink from Task** for a subtask). In the displayed modal, select additional entity if desired. You
are asked to confirm before finalizing the action.

To delete tasks and subtasks, select **more options** icon for the target row and select **Delete**.

Note:

Unlinking is available for partially unlocked tasks or subtasks. Unlinked entities
become orphan and are only viewable in the Orphan list view. Be careful when unlinking
entities from their parents as you cannot re-link to a parent from the user interface.
If re-linking is required, use the Object Import function where you can specify the
parents in a JSON file.

You can also configure events in bulk, either using JSON or the UBP. For more information,
see [Bulk Configuring Events](bulk-configuring-uds-entities.html#topic315301_5_8__bulk-configuring-events_html).

**Managing Orphan Objects**

When you import UDS activities in bulk through UI Bulk Import or User Bucket for Partners,
you can create tasks or subtasks which are not linked to any parents. These unlinked
tasks or subtasks are called "orphan" objects. You can also create orphan objects when you unlink publish tasks or subtasks
from parents using the UDS Management Tool. These orphan objects may cause error in
diagnostic tests during the NP Config Tag creation.

User Permissions and Limitations

If you are a "Viewer" title collaborator, you can view orphan object listings. In order to delete UDS orphan
objects, you must have either "Editor" or "Owner" title collaborator roles.

View the List of Orphan Objects

You can access the list of orphan objects using the object definition viewer. Select
**Actions > Manage Orphan Objects** to access this view. Orphan list view provides independent tabs for tasks and subtasks.
If an orphan task is associated with child subtasks, you can expand the row to view
the list of subtasks. The UDS Management Tool does not support editing orphan objects
or re-linking orphans to existing parents.

Orphan List View

Deleting All Orphans

You can remove all orphan objects by clicking **Delete All** button. You are prompted to confirm the action. Published orphan objects cannot be
deleted, but do not cause any future submission issues.

Note:

You can also remove all orphan objects by using **Delete All Objects and Overwrite** when importing JSON files.

Delete All Orphans

## Configuring Events

**User Permissions and Limitations**

If you are a "Viewer" title collaborator, you can view existing UDS event definitions. In order to create
or edit an event, either "Editor" or "Owner" title collaborator roles are required. UDS supports up to 512 events per NP Communication
ID. Each event can specify up to 32 properties.

Note:

Some events may be created automatically by the trophy tool. Events that are generated
from the trophy tool is displayed in the list but are not editable.

**View the List of Defined Events**

You can access the list of defined UDS events using the Event Viewer. Select **Define Data > Events** to access this view. The Event Viewer shows the following high-level event information:

* **Event Name:** User specified unique identifier of the event.
* **Event Type:** Type of the event. For a list of supported event types, see [UDS Data Model](uds-data-model.html "UDS standardizes data required by each platform feature and defines it in the UDS data model. By doing so, it prevents the duplication of data received from a game application and realizes single input multi-use. A UDS data model is composed of a PlayStation™Network object and a UDS event (feature event).").

Selecting a row in the list displays the defined properties for the selected event,
shown in the following figure, the UDS-defined feature properties for each event type.
Refer to [UDS Event Reference](uds-event-reference.html "This topic contains UDS event names and property descriptions.") for the list of properties defined for each type of feature event. If the selected
event contains custom properties, these properties also appear.

Defined Properties

**Create a New Event**

You can create a new event by selecting the **Actions** button on the Event Viewer then selecting **Create New Event**. This selection displays the Create New Event Definition page, shown in the following
figure.

Create New Event Definition

The following steps are required to create a new event:

1. Select the **Event Type**. Choose from the supported UDS event types.
2. UDS Management tool populates the **Event Name** field with the selected event type name. The event name is the unique identifier
   for the event. Update the event name to ensure the uniqueness.
3. If there is a selected event type, the list of properties is populated. Assign an
   alias to each of the feature properties, if necessary. Games use these aliased names
   as parameter names when sending events to UDS. UDS uses the event definition to map
   the parameter value referenced by the alias to the appropriate feature property.
4. If the feature property is optional, you can remove it. Select the X icon to remove
   the optional feature property. Removed feature properties can be added back by selecting
   +Add System Properties. This button is only displayed if one or more optional feature
   properties are removed from the event.
5. Add custom properties to the event, if desired, by selecting the **+ Add Custom Property** button. Each custom property requires a property name and data type.

   Note:

   Property names cannot start with "\_" (underscore). If the "array" data type is specified, the object type (data type of the array element) must also
   be provided.

   Removing Optional Properties

**Edit an Existing Event**

You can edit an existing event from the Event Viewer. Specify the event to edit by
selecting the **more options** icon for the event, then select the **edit** option. This option displays the event definition edit view for the selected event.

The UDS Management Tool supports deep linking to the event edit screen. If you want
to share event information with other users, you can share the URL of the edit page.
The other user can then access the event edit page directly with the shared URL.

Note:

The tool allows you to modify the property name or delete a custom property referenced
by stats extraction rules. Be careful when modifying or deleting existing properties.
Some of the events do not have an edit option if the events are auto-generated by
the trophy system.

Note:

Once a UDS event is added to NP Config Tag, it may be in a Locked or Partially Unlocked
status. Events in the Locked status cannot be modified. Events in the Partially Unlocked
status supports only adding new properties.

**Delete an Existing Event**

You can delete an existing event from the Event Viewer. Specify the event to edit
by selecting the **more options** icon for the event, then select the **delete** option.

Note:

The tool allows you to delete the events referenced by stats extraction rules. Be
careful when deleting an event.

You can also configure events in bulk, either using JSON or the UBP. For more information,
see [Bulk Configuring Events](bulk-configuring-uds-entities.html#topic315301_5_8__bulk-configuring-events_html).

## Configuring Stats

**User Permissions and Limitations**

If you are a "Viewer" title collaborator, you can view existing stats definitions. In order to create,
edit, or delete a stats definition, either "Editor" or "Owner" title collaborator roles are required. UDS supports up to 512 stats definitions per
service label (NP Communication ID). You can define a maximum of six stats definitions
marked as **Show Stat on Player's Profile**.

Note:

Stats definitions generated by the trophy system are displayed in the list but are
not editable.

Events generated by the trophy system cannot be used in the stats extraction rules.

**View the List of Stats Definitions**

You can access the list of current stats definitions using the stats definition list
viewer. Select **Define Data > Stats** to access this view. The stats definition list viewer shows the following high-level
Stats definition information:

* **Stat Name:** Name of the stats definition.
* **Source:** Source of the stats definition. When the source is "custom", the stats definition is created manually through the UDS Management Tool. When the
  source is "Auto Gen For Trophy", the stats definition is generated though the trophy system. "Auto Gen For Trophy" stats cannot be modified using the UDS Management Tool.
* **Type:** Data type of the stats definition. For the supported data types, refer to [UDS Data Model](uds-data-model.html "UDS standardizes data required by each platform feature and defines it in the UDS data model. By doing so, it prevents the duplication of data received from a game application and realizes single input multi-use. A UDS data model is composed of a PlayStation™Network object and a UDS event (feature event).").
* **Aggregation:** How the stat is aggregated in the list, i.e. count, latest, sum etc.

Selecting a row in the list displays the detailed information for the selected stats
definition. Refer to the [UDS Data Model](uds-data-model.html "UDS standardizes data required by each platform feature and defines it in the UDS data model. By doing so, it prevents the duplication of data received from a game application and realizes single input multi-use. A UDS data model is composed of a PlayStation™Network object and a UDS event (feature event).") for the description and list of properties for stats definitions. In addition to
the stats definition properties, the UDS Management Tool also displays the list of
stats extraction rules for the selected stats definition. Stats extraction rules define
how to extract the stat information from UDS events.

**Create a New Stats Definition**

You can create a new stats definition by selecting **Create New Stat** button on the stats definition list viewer. This displays the stats definition creation
page. Following steps are required to create a new stats definition:

1. Specify the name of the stats definition.
2. Select the data type.
3. Specify the Base Properties for the stats definition. Base properties include the
   following fields:

   * **Aggregation**. Specifies the aggregation method of this stat.
   * **Initial value**. Specifies the initial value for this stat.
   * **Max value**. Specifies the maximum value for this stat.
   * **Min value**. Specifies the minimum value for this stat.

     Note:

     The selected data type determines the available aggregation options as well as other
     base properties.
4. Create one or more stats extraction rules. Stats extraction rules determine how to
   extract the stat information from UDS events. Create new stats extraction rules by
   selecting the **Add Extraction** button. Stats extraction requires the following information:

   * **Event Name**. Name of the event from which this stat is calculated. Events generated by the trophy
     system are not available for stats extractions created though the tool.
   * **Extraction Condition**. Specifies the condition that must be matched in order to extract the stats. Extraction
     condition is optional. If no condition is specified, only the event name is checked
     when extracting the stats. An extraction condition consists of the property name,
     operator, and the value. The property name must be one of the properties defined in
     the specified event.
   * **Action**. Specifies which event property is assigned to the stat. Value is assigned based
     on the aggregation method specified in the base properties of this stats definition.

**Edit an Existing Stats Definition**

You can edit an existing stats definition from the stats definition list viewer. Specify
the stats definition to edit by selecting the **more options** icon for the stats definition, then selecting the **edit** option. This displays the stats definition edit view for the selected object.

You can add, edit, or delete stats extraction rules when editing a stats definition.
In order to add new stats extraction rules, select the **Add Extraction** button. Selecting the **more options** icon for existing stats extraction rules shows **delete** and **edit** options.

The UDS Management Tool supports deep linking to the stats definition edit screen.
If you want to share stats definition information with other users, you can share
the URL of the edit page. The other user can then access the stats definition edit
page directly with the shared URL.

Note:

Once a UDS stat definition or extraction is added to NP Config Tag, the entity maybe
in a Locked or Partially Unlocked status. Stats definitions in the Locked status cannot
be modified. Stats definitions in the Partially Unlocked status cannot be modified
but new stats extractions can be added. Refer to the [UDS Data Model](uds-data-model.html "UDS standardizes data required by each platform feature and defines it in the UDS data model. By doing so, it prevents the duplication of data received from a game application and realizes single input multi-use. A UDS data model is composed of a PlayStation™Network object and a UDS event (feature event).") for details.

**Delete an Existing Stats Definition**

You can delete an existing stats definition from the stats definition list viewer
by clicking the ellipsis, in line, and selecting **delete**. Stats definitions generated from the trophy system cannot be deleted

You can also configure stats in bulk, either using JSON or the UBP. For more information,
see [Bulk Configuring Stats](bulk-configuring-uds-entities.html#topic315301_5_8__bulk-configuring-stats_html).

## User Bucket for Partners (UBP)

Management of a large number of UDS related entities (PlayStation™Network objects,
UDS events, or UDS stats definitions) and associated media files (images and videos)
may be required for some games. Uploading and associating the media files manually
though a web-based interface is time consuming. User Bucket for Partners (UBP) simplifies
the management of assets by supporting SFTP based bulk upload process to an Amazon
S3 bucket:

* Activity, Task, and Subtask
* Zone
* Mechanic
* Actor
* Subcategory
* TrophySet/TrophyGroup/Trophy
* Stat Definition/Extraction
* UDS Event
* Tournament

The UBP is designed to address the following use cases:

1. Package both entity definitions and associated media together and submit. This use
   case is best suited when both entity definitions and associated media files are available
   together. If included entities are new, UBP creates new entities with associated media
   files. If included entities already exist, entity metadata is updated, and newly uploaded
   media files are associated. You can review the result of the creation or update in
   the UDS Management Tool after the process completion.
2. Package media files for already existing entities. This use case is best suited when
   target entities are already created in the UDS Management Tool. Packaged media files
   are automatically associated with the target entities. If the target entity is already
   associated with media files, the newly uploaded media files replace the existing ones.
3. Package media files for entities to be created later. This use case is best suited
   when the target entities are yet to be created. UBP stages the uploaded media assets.
   Media assets are automatically associated to the target entities upon creation.
4. Package metadata only without any associated media. This applies to both entities
   with media support (PSN Objects and Trophies) and entities without media support (UDS
   events, stat definitions, stat extractions).

   Note:

   The current version of UBP does not support manual association of the uploaded media
   asset via the web-based interface. Make sure to specify the correct target entities
   for both User Case 2 and 3.

**Creating Media Package**

UBP expects all related files to be packaged into a tar file (`.tar` or `.tar.gz`). A package (tar file) should contain a `metadata.json` file and all associated media files. The `metadata.json` file describes properties for included entities along with the references to packaged
media files. The structure of `metadata.json` file is entity and use case dependent. The specification is described in [JSON Structure for Importing & Exporting Objects](bulk-configuring-uds-entities.html#topic315301_5_8__json-structure-for-importing-exporting-objects_html). The file name is case sensitive (`metadata.json` should be named with all lower-case letters). Refrain from using a space in the tar
file name.

Note:

The current version of UBP requires tar package creation even for metadata-only submission
with one file.

**User Bucket for Partners Useful Information**

1. How does User Bucket for Partners handle partial failures?

   UBP processes as many files as possible. If one of the included entities encounters
   issues (invalid metadata, media files not meeting the spec requirements), UBP logs
   the error and process the rest of the entities. Once process completes, the email
   notification includes the error information.
2. What should I do when my file has a partial failure and I want to re-submit?

   The bulk upload process is re-entrant. Simply update the erroneous records or files
   in the package and re-submit the file.
3. Why does the file name change when I check the uploaded image file from UDS Management
   Tool UI?

   When media files are submitted, UBP uploads media files to the CDN. During the upload
   process, UBP generates a unique new file name in order to avoid a conflict with previously
   uploaded files. UDS Management Tool displays the system generated file name.
4. What happens if the metadata.json file for the use case 1 does not contain existing
   entities?

   UBP only affects the entities included in a `metadata.json` file. Entities not contained in the JSON file are not affected.
5. How does User Bucket for Partners update existing entities?

   UBP performs entity update by replacement. If the entity metadata in `metadata.json` does not contain a property defined in the UDS Management Tool, the property is deleted
   after update.
6. Can I reference the same media file from multiple entities in metadata.json?

   It is possible to reference the same media files from multiple entities in `metadata.json`.
7. Are there any limitation on the package size?

   UBP does not restrict the number of entities defined in a `metadata.json` or the package (tar) file size.

## State of a User

You can use the UDS Management Tool to view the state of a user.

To view the state of a user:

1. Click the **View Data** tab in the UDS Management Tool, then click **State**.
2. Select the system language to view.
3. Enter the Online ID for the account to view in the **Account for PSN** search area.
4. Click the blue **Magnifying Glass** icon to the right of the **Online ID** text on the top of the page.

The state viewer displays the following information for activities:

* UDS states are organized into columns with a checkmark next to the applicable state:
  + *Ever Available* - Activities that have ever been made available using an `activityAvailabilityChange` event.
  + *Ever Played* - An `activityStart` or `activityEnd` event has ever been sent for the activity.
  + *Ever Completed* - An `activityEnd(outcome: completed)` event has ever been sent for the activity.
* *Standard Progress* - Shows the activity's progress as a percentage based on the number of required tasks and sub-tasks the player has ever completed and the remaining number of required tasks and sub-tasks to complete. For example, if an activity includes five required tasks and the player has ever completed two of those tasks, 40% is shown. Progress does not reset. This is the default UX shown on the face of activity cards in the system software as of the 10.2 firmware update.
* *Resettable Progress* - Shows the activity's progress as a percentage based on the number of required tasks and sub-tasks the player has completed in the most recent instance of the activity, and the remaining number of required tasks and sub-tasks to complete. For example, if an activity includes five required tasks and the player has completed two of those tasks in the most recent instance, 40% is shown. The most recent instance of the activity can be reset by sending a new start event for the task, sub-tasks, or the parent activity. This was the default UX shown on the face of activity cards prior to the 10.2 firmware update.

The state viewer displays respective UDS states for other PlayStation™️Network object types:

* *Zone*: Ever Been and Latest.
* *Mechanics*: Available, Unavailable, Ever Used, Ever Seen, Latest Equipped, and Latest Inventory.
* *Actors*: Ever Selected, Ever Seen, Latest Primary, and Latest Secondary.

States are organized into columns and PlayStation™️Network objects with respective states are marked with a checkmark.

## Configuring Tournaments

You can perform several actions with tournaments from **Actions**:

* Create a new tournament.
* Import tournaments (.json)
* Export Tournaments (.json)

**Create a Tournament**

To create a tournament, click **Actions** > **Create New Tournament**. This takes you to a tournament configuration page with the following sections:

* Attributes
* Rules
* Scheduling
* Statistics
* Rewards
* Localization.

From the **Attributes** tab, you can configure the following fields:

* **Object ID** -- A unique identifier.
* **Subcategory** -- The subcategory for the tournament. You can localize tournament subcategories.
  For more information, see [Tournament Subcategories and Tournament Subcategory Localization](configuring-metadata.html#topic315301_5_6__tournament-subcategories-and-tournament-subcategory-localization_html).
* **Display Name** -- The name that appears on the tournament's activity card.
* **Game Mode** -- The mode of competition for the tournament.
* **Tournament Format** -- The format for the tournament. Only the `symmetricSingleElimination` format is supported.
* **Is Team Tournament** -- Specifies if the tournament is a team tournament. If selected, the associated activity must be a team activity.
* **Activity** -- The associated activity for the tournament. Must be a competitive activity.
* **Zone** -- The zone where the tournament will take place.

Additionally, you can set images associated with the tournament.

Attributes Tab

From the **Rules** tab, you can configure the following fields:

* **Minimum Number of Rounds** -- The minimum number of rounds for the tournament. If the minimum number of players
  to satisfy this value is not met, the tournament is canceled.
* **Maximum Number of Rounds** -- The maximum number of rounds for the tournament.
* **Maximum Match Length** -- Maximum time length for a tournament match. Must be a minimum of one minute, and
  a maximum of three hours.
* **Waiting Expiration Time** -- The time a user has to accept a tournament invitation before it expires.
* **Country Age Rules** -- A list of countries and regions where the tournament is available and the minimum
  age requirement for each country.
* **Rules File** -- A file containing the tournament rules. Rules file must have a `.txt` extension. Contents of the file can include `<BR>`, `<I>`, `<EM>`, `<B>`, `<STRONG>`, `<P>`, `<DIV>`, `<SPAN>`, and `<FONT>` tags for HTML formatting. Only `font-weight`, `font-style`, and `color` attributes are supported.
* **Rules Acceptance Required** -- Specifies if accepting tournament rules is required for a player to register in the tournament.
  Rules Tab

From the **Scheduling** tab, you can configure the following fields:

* **Available From/To** -- Specify a time window when the tournament is available.
* **Availability Before Start** -- Specifies the time a tournament is open for registration before it starts. If
  you do not specify this parameter, users can register as soon as the scheduler creates
  the tournament occurrence.
* **Repeatable** -- If checked, allows you to set a recurring schedule for the tournament. When specifying
  a recurring schedule, you can set up to two timeslots per day of the week.
  Scheduling Tab

From the **Statistics** tab, you can specify up to 10 statistics requirements for the tournament. For each
statistics requirement, specify:

* **Stat Name** -- A stats definition you've created for the current NP Communication ID.
* **Operator** -- An operator (&gt;=, &gt;, &lt;, &lt;=) for the condition.
* **Target Value** -- A target value for the condition.

  Stats Tab

From the **Rewards** tab, you can specify up to 10 rewards for the tournament. For each reward, you can
specify a **Reward Name** and a **Reward Image**.

There are additional options for each reward:

* **Minimum Rank** -- Minimum rank required for a player to qualify for the reward.
* **Maximum Rank** -- Maximum rank for a player to qualify for the reward.
* **SKU** -- The SKU of the reward granted to the player. Used for automatic rewards.

  Rewards Tab

From the **Localization** tab, you can localize the tournament's display name, game mode text, and rules.

To publish selected tournaments:

1. Click **Action** > **Bulk Publish Tournaments**. You can select and publish up to 10 tournaments at a time. You can select the desired

   Bulk Publish Tournaments View

To run an integrity check on all defined tournaments:

1. Select **Publishing** > **Integrity Check**.

   Integrity Check

If the integrity check generates any errors, warnings, or informational messages,

If the integrity check generates any errors, warnings, or informational messages,
