# Token Revocation Endpoint

# revokeToken

Revoke an access token or refresh token

### Description

Revoke an access token or refresh token issued to the client making the revocation request. The client must authenticate using HTTP Basic authentication scheme as defined in [RFC7617](https://tools.ietf.org/html/rfc7617).

Revoking a refresh token does not automatically revokes all access tokens issued based on the same authorization grant.

**Examples:**

**Example 1: Revoke a refresh token**

```
curl -X POST \
    -H "Authorization: Basic {base64encode({clientId} + ':' + {clientSecret})}" \
    'https://s2s.sp-int.playstation.net/api/authz/v3/oauth/revoke' \
    --data-urlencode "token={refreshToken}" \
    --data-urlencode "token_type_hint=refresh_token"
```

**Response** For a valid request, the response is always 200, even when token submitted is invalid or has expired.

```
HTTP/1.1 200 OK
Cache-Control:"no-store"
```

If the client of the refresh token has consent enabled, then all underlying consent is revoked as well.

### Request

```
POST /v3/oauth/revoke
```

### Header Parameters

| Name | Type | Required | Description |
| --- | --- | --- | --- |
| X-Psn-Origin-Client-Ip | **string** | false | The IP address of the device of end-user that originates the request. This is used for security purposes. |

### Request Body

**Content-Type:** application/x-www-form-urlencoded

| Parameter | Type | Required | Description |
| --- | --- | --- | --- |
| » token | **string** | true | The token to be revoked. |
| » token\_type\_hint | **string** | false | The type of token to be revoked. This field is optional but should be submitted. An invalid value for token\_type\_hint will be ignored by the authorization server and does not influence the revocation response.  **Possible Values:**  - access\_token  - refresh\_token |

### Responses

| Status | Meaning | Description |
| --- | --- | --- |
| 200 | [OK](https://tools.ietf.org/html/rfc7231#section-6.3.1) | The token has been revoked successfully or is not a valid token.  Note that the authorization server may return HTTP status code 400 with invalid\_request error  if the token is not in expected format. The client should log and verify that this is expected  in client implementation. |
| 400 | [Bad Request](https://tools.ietf.org/html/rfc7231#section-6.5.1) | Bad request. |
| 401 | [Unauthorized](https://tools.ietf.org/html/rfc7235#section-3.1) | Unauthorized. |
| 429 | [Too Many Requests](https://tools.ietf.org/html/rfc6585#section-4) | The request has been rate limited. |
| 500 | [Internal Server Error](https://tools.ietf.org/html/rfc7231#section-6.6.1) | Internal server error. |
| 503 | [Service Unavailable](https://tools.ietf.org/html/rfc7231#section-6.6.4) | Service unavailable. |
