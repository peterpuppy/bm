# Changing the Members of a Game Session

# leaveGameSession

Makes the member leave the Game Session

### Description

This request makes the member (player or spectator) specified with *accountId* leave the Game Session.  
For *accountId*, you can specify only either me, indicating the user linked to access token, or the *accountId* of the user linked to the access token.

If the specified member has a reservation to join the session as a player (*joinState*=RESERVED), the reservation will be canceled.  
If the number of participating players after the player leaves becomes 0, the Game Session will be deleted.

**Change of Representative**

If the specified member was the representative for the session, the remaining player with the oldest join date and time in the Game Session will become the new representative.  
If there are multiple players with the same join date and time, the one with the smallest Account ID becomes the representative.

Note that when the request is called from an application server, it is not possible to use an access token obtained using the authentication feature for websites.

# joinGameSessionAsPlayer

Adds a player to the Game Session

### Description

This request makes the user specified with *players* join the Game Session as a player.

**Join a Session**

The conditions for a joinable Game Session are as follows.

* *joinDisabled* must be false for the Game Session
* The number of players participating in the Game Session must be fewer than the maximum number of players who can participate

The conditions for the users who can join are as follows.

* If the specified Game Session is dependent on a Player Session, the user must be participating in one of the Player Sessions as a player
* Must not already be participating in the specified Game Session as a player (joining is possible, even with the same account ID, if the platforms differ)

Additionally, the following conditions apply to the parameters specified for each user.

* The user linked to the access token  
  + me can be specified for *platform*
  + Only *joinState*=JOINED can be specified
  + Specification of Push context information is required
* A user not linked to the access token  
  + me cannot be specified for *platform*
  + Only *joinState*=RESERVED can be specified
  + Push context information cannot be specified

**Swapping from Spectator to Player**

If a user has already joined a requested Game Session as a spectator, he or she can swap roles from spectator to player.

The conditions under which a swap from a spectator to a player in a Game Session is possible are as follows.

* The number of players participating in the Game Session must be fewer than the maximum number of players who can participate
* If the specified Game Session is dependent on a Player Session, the user linked to the access token must be participating in the Player Session as a player

Note that when the request is called from an application server, it is not possible to use an access token obtained using the authentication feature for websites.

**Example Request**

```
{
  "players": [
    {
      "accountId": "me",
      "platform": "PS5",
      "pushContexts": [
        {
          "pushContextId": "c1731f55-d24e-c556-cb77-b37faf5a832a"
        }
      ],
      "natType": 1,
      "joinState": "JOINED",
      "customData1": "TWVtYmVyIEN1c3RvbSBEYXRhMQ=="
    }
  ]
}
```

**Example Response**

```
{
  "players": [
    {
      "accountId": "123456789",
      "platform": "PS5"
    }
  ]
}
```

# joinGameSessionAsSpectator

Adds a spectator to the Game Session

### Description

This request makes the user specified with *spectators* join the Game Session as a spectator.

**Join a Session**

The conditions for a joinable Game Session are as follows.

* *joinDisabled* must be false
* The number of spectators currently joined must be fewer than the maximum number of spectators who can join

The conditions for the users who can join are as follows.

* For *accountId*, you can specify only either me, indicating the user linked to access token, or the *accountId* of the user linked to the access token
* For *platform*, you can specify only either me, indicating the platform of the user linked to access token, or the platform of the user linked to the access token
* If the specified Game Session is dependent on a Player Session, the user must be participating in one of the Player Sessions as a player or as a spectator
* Must not already be participating in the same Game Session as a spectator (Joining is possible if it is from a different platform)

Note that there is no limit on a user simultaneously participating in multiple Game Sessions.

**Swapping from Player to Spectator**

If the user has already joined the requested Game Session as a player, he or she can swap roles from player to spectator.

The conditions under which a swap from a player to a spectator in a Game Session is possible are as follows.

* The number of spectators currently joined must be fewer than the maximum number of spectators who can join
* The user linked to the access token must not be the only player in the Game Session

Note that when the request is called from an application server, it is not possible to use an access token obtained using the authentication feature for websites.

**Example Request**

```
{
  "spectators": [
    {
      "accountId": "me",
      "platform": "PS5",
      "pushContexts": [
        {
          "pushContextId": "c1731f55-d24e-c556-cb77-b37faf5a832a"
        }
      ],
      "natType": 1,

}
```
