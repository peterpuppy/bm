# Activity Object Structure

This chapter provides information on the PlayStation™Network Object structure of activities, tasks, and sub-tasks.

# Activity Types

This topic provides information on activity object structure, including activity types and how they are used.

Activities are the highest level object in the PlayStation™Network Object structure and represent a segment of gameplay such as a level, mission, chapter, quest, objective, or game mode.

Ensuring that create an activity for each major area of your game and properly managing the state of those activities allows players to find more information about what they’re doing, make them aware of new things they could be doing, and notify them of what their friends are doing in your game.

There are four types of activities that represent different types of content:

* Progress activities
* Open-ended activities
* Competitive activities
* Challenge activities

## Progress Activities

Progress activities represent segments of a game that have clearly defined start and end points. Missions, chapters, or levels in a campaign or story mode are the most common example of a progress activity. You can maximize the benefit of progress activities by breaking down gameplay segments into smaller objectives using tasks that are linked to the activity.

Progress activities include the following functionality:

* Game Help videos which generated by Community Game Help. This is the only activity type that generates Community Game Help videos.
* Playtime estimates that show players how long it may take to complete the activity
* When tasks are configured, players can view a completion percentage based on how many tasks they have completed.

Do not end progress activities that you've configured as single player, where the number of players is 1 or blank, unless players have successfully completed the activity. Send the `activityEnd (outcome: completed)` event in these cases.

SIE does not recommend configuring progress activities as multiplayer. If you do, you must use the Matches Web API to update the activity's state and you must send the `SUCCESS` or `FAILED` outcomes with the `reportResults` request.

For more information on managing state and visibility, see [Managing the State of Activities, Tasks, and Sub-tasks](managing-state-of-activities.html "This chapter provides information on how to manage the state of activities, tasks, and sub-tasks.").

## Open Ended Activities

Open-ended activities represent segments of gameplay players can play indefinitely, such as creator/build modes, or simulation style games without defined endings or objectives. They also represent repeatable game modes that players can play solo or with other players locally.

Open-ended activities can include tasks. You can manually link Custom Game Help to open-ended activities and their tasks, but PlayStation™Network does not generate Community Game Help videos for them.

Open-ended activities enhance players' presence state on the platform. When looking at another player's profile, instead of seeing the title of the game they are playing, players can to view an activity of the game mode.

Manage single player open-ended activities with UDS events and multiplayer ones with the Matches Web API.

For more information on managing state and visibility, see [Managing the State of Activities, Tasks, and Sub-tasks](managing-state-of-activities.html "This chapter provides information on how to manage the state of activities, tasks, and sub-tasks.").

## Competitive Activities

Competitive activities represent gameplay segments where a winner and loser is determined based on the outcome of synchronous competitive play. For example, a deathmatch mode in a first-person shooter game, a race in a racing game, or a match in a sports game. Competitive activities can be player vs. player, player vs. computer, or a combination of the two.

Competitive activities can include the following information depending on what data you send using the Matches Web API:

* Required - The players involved in the current match, separated by team if applicable
* Required - Match results, winner and losers

* Optional - The current score of the match
* Optional - Custom statistics for the game mode that can be updated in real time or after the match

You can only manage competitive activities using the Matches Web API. For more information on how to manage competitive activities, see [Matches Web API Overview](../../../WebAPI/latest/Matches_WebAPI-Overview/__document_toc.html).

## Challenge Activities

Challenge activities represent repeatable gameplay segments where players are measured by time or score. For example:

* A mode in a puzzle game where the player must clear the board as fast as possible or achieve the highest score possible within a set time or before reaching a fail state
* Challenge missions with a scoring system
* Mission replays or speedrun modes with a scoring system
* Boss rush modes

You can configure challenge activities to create asynchronous multiplayer for these single player games and modes, including functionality such as:

* Leaderboards viewable within the PlayStation®5 system software
* Notifications that are sent when a friend gets a better score
* Invite flows to attract new players or re-engage lapsed players

When a player completes a playthrough of a challenge activity, their result is passed along with the `activityEnd` event and shown on the leaderboard on the Challenge Activity Card. The leaderboard shows two categories of results: global (if enabled for the challenge) and friends-only.

Challenge activities must be repeatable.

For more information on challenge activities, see "PlayStation™Network Challenge Activity Guide".

# Tasks and Sub-tasks

This topic provides information on task and sub-task object structure.

You can use tasks and sub-tasks to break progress and open-ended activities into smaller objectives.

This is helpful when the parent activity takes the average player longer than 15 minutes to complete or if the parent activity requires multiple steps that can explained one at a time.

The following examples highlight game designs that allow you to use tasks effectively:

* Games with missions, chapters, or levels that require the player to complete multiple objectives. Represent each objective as a task attached to the parent activity that represents the mission.
* Games with collectibles. Configure a progress activity that represents a collectible type, and tasks that represent each individual collectible. As players find each collectible, mark each task as completed so players can see what they haven’t found yet.
* Games with boss fights where the boss has distinct waves or patterns. Represent each wave or pattern as a separate task.

If none of the scenarios above apply to your game, consider creating tasks based on when your game triggers autosaves or checkpoints.

Game Help videos are always attached to the smallest object in the structure, including videos that are automatically generated from Community Game Help. Players can more quickly find videos for the individual tasks they need help with, rather than watching a longer video that covers the entire activity.

Required tasks contribute to the game completion percentage shown to players on the Game Hub.

Sub-tasks function the same as tasks and are represented the same in the UI. For example, if you configure sub-tasks but do not name them, they appear with the same default name of "Objective Part 1", "Objective Part 2", etc. For this reason, SIE does not recommend that you configure sub-tasks, and instead only use tasks for all appropriate situations.

## Activity, Task, and Sub-task Limit

You can configure a total of 2560 PlayStation™Network Objects (activities, tasks, and sub-tasks) for a game.

For example, you can configure up to 2560 individual activities, or a single activity that has 2559 tasks. Once you publish UDS events to production, you can't delete them.
