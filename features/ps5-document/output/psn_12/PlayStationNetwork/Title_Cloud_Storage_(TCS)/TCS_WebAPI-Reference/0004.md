# Variables

# setMultiVariablesByUser

Write TCS variables

### Description

This request writes a TCS variable to a slot owned by the specified user. If the specified user is anyone, the write destination will be a slot owned by the title.

You can write different values, respectively, to multiple slots at once. If multiple slots are specified, an error will occur if even one write operation fails. If this happens, then it is possible that writing succeeded for other TCS variables, which will have been updated. Therefore, if an error is received, re-run the request.

It is recommended from a performance and load perspective that the number of slots to write to at once be 64 or less.

**Example Request**

```
PUT titleCloudStorageBaseUrl/v1/apps/myApp/users/1234567890/variables

{
  "variables": [
    {
      "slotId": 0,
      "value": "0"
    },
    {
      "slotId": 1,
      "value": "1"
    }
  ]
}
```

HTTP status 204 will be returned when the above request example succeeds. There will be no response body.

# getMultiVariablesByUser

Read TCS variables

### Description

This request reads a TCS variable from a slot owned by the specified user. If the specified user is anyone, the read source will be a slot owned by the title.

You can read TCS variables from multiple slots at once. The maximum number of slot IDs that can be specified at once is 128, and an error will occur when exceeding this value.

By default, the results of reading will be sorted in ascending order by slot ID. It is also possible to specify the last update date or the variable value as the sorting condition.

An error will not occur if a slot that hasn't been configured yet or a slot that has been deleted is specified, but that slot won't be included in the response. If all the specified slots have not been configured yet or have been deleted, an empty response will be returned.

If multiple slots are specified, there will be an error if even a single read operation fails.

**Example Request**

```
GET titleCloudStorageBaseUrl/v1/apps/myApp/users/1234567890/variables?slotIds=0,1
```

**Example Response**

```
{
  "variables": [
    {
      "slotId": 0
      "owner": {
        "accountId": "1234567890",
        "onlineId": "strongJohn"
      },
      "lastUpdatedUser": {
        "accountId": "4567890123",
        "onlineId": "luckyTom"
      },
      "lastUpdatedDateTime": "2020-01-23T04:56:07.00Z",
      "value": 0
    },
    {
      "slotId": 1
      "owner": {
        "accountId": "1234567890",
        "onlineId": "strongJohn"
      },
      "lastUpdatedUser": {
        "accountId": "1234567890",

      },
      "lastUpdatedDateTime": "2020-01-23T04:56:07.00Z",
      "value": 1

}
```

# deleteMultiVariablesByUser

Delete TCS variables

### Description

This request deletes a TCS variable from a slot owned by the specified user. If the specified user is anyone, a slot owned by the title will be subject to having its data deleted.

You can delete TCS variables from multiple slots at once. The maximum number of slot IDs that can be specified at once is 128. Specifying a number of slots above that limit will result in an error. If multiple TCS variables are specified, there will be an error if even a single deletion fails. If this happens, then it is possible that other TCS variables have been successfully deleted. If processing for deletion is performed on an already deleted or non-existent slot, there will be no error. Therefore, if an error is returned, it is fine to re-run the request without changing the target slots.

**Example Request**

```
DELETE titleCloudStorageBaseUrl/v1/apps/myApp/users/1234567890/variables?slotIds=0,1,3
```

HTTP status 204 will be returned when the above request example succeeds. There will be no response body.

# addAndGetVariable

Add a value to a TCS variable and read the result

### Description

This request adds a 64-bit integer value to a slot owned by the specified user. If the specified user is anyone, a slot owned by the title will be subject to addition. Specify a 64-bit integer value to be added for *value*. It is also possible to perform subtraction by specifying a negative number.

If the result after addition is performed is outside the valid range that has been set beforehand for the TCS variable, the value will be rounded to either the maximum or minimum values that have been set and then stored. If a numerical value has yet to be set to the TCS variable, processing will occur as though 0 had been set.

If an account ID has been specified for *comparedLastUpdatedUserAccountId*, addition and writing is performed only if the latest updater recorded for the slot is equal to that value. If a time has been specified for *comparedLastUpdatedDateTime*, addition and writing is performed only if the latest update date and time recorded for the slot is equal to that value. If, at the same time, both values have been specified, addition and writing is performed only if both conditions are met. This feature is intended to be used for mutual exclusion, such as when multiple users operate on the same slot and you only want to reflect the operations of the first user.

**Example Request**

```
POST titleCloudStorageBaseUrl/v1/apps/myApp/users/1234567890/variables/slots/0/add

{
  "comparedLastUpdatedDateTime": "2019-01-10T03:53:16.00Z",
  "comparedLastUpdatedUserAccountId": "1234567890",
  "value": "7"
}
```

**Example Response**

```
{
  "owner": {
    "accountId": "1234567890",
    "onlineId": "strongJohn"
  },
  "lastUpdatedUser": {
    "accountId": "1234567890",
    "onlineId": "strongJohn"
  },
  "lastUpdatedDateTime": "2019-01-23T04:56:07.00Z",
  "value": 8,
  "prevValue": 1,
  "slotId": 0
}
```

# setVariableWithConditions

Write to a TCS variable conditionally

### Description

This request writes a TCS variable to a slot owned by the specified user. Looks up the existing value before writing, and only performs the write operation if the specified condition has been met. If the specified user is anyone, the write destination will be a slot owned by the title. Specify a 64-bit integer value to be compared with the existing value for *comparedValue*. If you do not specify anything for *comparedValue*, the value specified for *value* will be compared to the existing value. Specify one of the following strings for *condition*:

* equal: Writes if *comparedValue* (or *value*) is the same value as the existing value
* not-equal: Writes if *comparedValue* (or *value*) is a different value than the existing value
* greater: Writes if *comparedValue* (or *value*) is greater than the existing value
* greater-or-equal: Writes if *comparedValue* (or *value*) is greater than or equal to the existing value
* less: Writes if *comparedValue* (or *value*) is less than the existing value
* less-or-equal: Writes if *comparedValue* (or *value*) is less than or equal to the existing value

Regardless of whether the condition is met, if the operation terminates normally, the TCS variable post-processing will be stored in the response and returned. If the value to be written is outside the valid range that has been set beforehand for the TCS variable, the value will be rounded to either the maximum or minimum values that have been set and then stored. However, the value before rounding will be used to determine the result of the comparison. If a numerical value has yet to be set to the TCS variable, processing will occur as though the condition has been met.

If an account ID has been specified for *comparedLastUpdatedUserAccountId*, addition and writing is performed only if the latest updater recorded for the slot is equal to that value. If a time has been specified for *comparedLastUpdatedDateTime*, addition and writing is performed only if the latest update date and time recorded for the slot is equal to that value. If, at the same time, both values have been specified, addition and writing is performed only if both conditions are met. If a condition is not met or a value has not been set for the slot or has already been deleted from it, an error is returned and writing is not performed. This feature is intended to be used for mutual exclusion, such as when multiple users operate on the same slot and you only want to reflect the operations of the first user.

```
  "value": "82"
}
```

# getMultiVariablesBySlot

Read TCS variables from multiple users

### Description

You can specify one slot ID and multiple account IDs and read the TCS variables owned by the users indicated by the IDs all at once. The maximum number of accounts that can be specified at once is 32. If you specify anyone, you can read TCS variables owned by the title at the same time.

By default, the results of reading will be sorted in ascending order by account ID (with anyone deemed as the having the highest-numbered account ID). It is also possible to specify the last update date or the variable value as the sorting condition.

An error will not occur if a slot that hasn't been configured yet or a slot that has been deleted is specified, but that slot won't be included in the response. If all the specified slots have not been configured yet or have been deleted, an empty response will be returned.

If multiple account IDs are specified, there will be an error if even a single read operation fails.

Note that the response will be extremely slow when group=friends is specified and there are many friends.

**Example Request**

```
GET titleCloudStorageBaseUrl/v1/apps/myApp/users/variables/slots/0?accountIds=1234567890,2345678901
```
