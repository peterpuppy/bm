# Stream Events

# getStreamEvents

Gets a list of events for a stream.

### Description

**Note:** This API is deprecated and will be removed on 30-Sep-2023. Transition to [getStreamEventsV2](0002.html#getstreameventsv2) as soon as possible.

Gets a list of events for a given stream.

Each event contains additional data that helps to identify transactions from the partner's side. For backwards compatibility of this API, additional data is not provided by default. You must set additionalData to true to receive additional data. Additional data fields in events are dynamic. SIE may add attributes to additional data in the future. Your client code should be able to handle new fields dynamically.

Please use [getStreamListInDetailV3](0002.html#getstreamlistindetailv3) API to get valid start position for the stream. API will throw error if start position is less than the valid start position mentioned in [getStreamListInDetailV3](0002.html#getstreamlistindetailv3) API

curl -X GET 'https://s2s.sp-int.playstation.net/api/partnerEventService/v1/partner-events/PARTNER178046/EVENTS-FOR-PARTNER0000-TITLES?startPosition=1' -H "Authorization: Bearer {access_token}"

# getStreamEventsV2

Gets a list of events for a stream with additional data

### Description

Gets a list of events for a given stream with additional data.

Each event contains additional data that helps to identify transactions from the partner's side.

**Standard Mode (Position-based)**

Please use [getStreamListInDetailV3](0003.html#getstreamlistindetailv3) API to get valid start position for the stream. API will throw error if start position is less than the valid start position mentioned in [getStreamListInDetailV3](0003.html#getstreamlistindetailv3) API

**Historical Event Retrieval (Date Range Filtering)**

This is only valid for event level streams.

You can retrieve historical events within a specific date range using the start and end query parameters. When using date range filtering: - Both start and end parameters are required together - The startPosition parameter is not required - Use nextPageToken from the response for cursor-based pagination - Maximum fetchSize is 500 events per request

**Pagination with pageToken**

When hasMore is true in the response, use the nextPageToken value from the response as the pageToken query parameter in your next request to fetch the next page of results. Continue until hasMore is false.
