# registerNotificationUrl

Register a Notification URL (Webhook) for an event type from the title stream

### Description

Add or update a notification URL for an event type from the title stream. Supported event types are delivered to this URL. Currently, only the SUBSCRIPTION event type is supported. Before registering a notification URL, confirm with SIE that the notification URL's domain has been added to the allowlist.

For an overview on the Event Push feature, see [Commerce Management Web API Overview - Using the Commerce Management Web API - Event Push](../Commerce_Management_WebAPI-Overview/event-push.html).

**Example: Register a Notification URL**

```
curl -X PUT 'https://s2s.sp-int.playstation.net/api/partnerEventService/v1/partners/PARTNER1/streams/STREAM1/eventTypes/SUBSCRIPTION' -H "Authorization: Bearer {access_token}"
```

**Request:**

```
{
"notificationUrl":"https://subs.api.partner1.net/api/v1/notify"
}
```

**Response:**

```
{
"status":"Success"
}
```

**Test Mode**

The optional testMode query parameter allows you to verify that your notification URL is working correctly:

* none: Default. Only saves or updates the notification URL.
* enqueue: Saves the URL and inserts a test event into the system, triggering the Event Push service to deliver a test notification to your webhook endpoint. The test notification event is sent through the production delivery pipeline after a successful response to verify end-to-end connectivity.

**Example: Register a Notification URL and Test a Push Notification**

```
curl -X PUT 'https://s2s.sp-int.playstation.net/api/partnerEventService/v1/partners/PARTNER1/streams/STREAM1/eventTypes/SUBSCRIPTION?testMode=enqueue' -H "Authorization: Bearer {access_token}"
```

**Request:**

```
{
"notificationUrl":"https://subs.api.partner1.net/api/v1/notify"
}
```

**Response:**

```
{
"status":"Success"
}
```

# addTitle

Adds a title ID to the title stream

### Description

Adds a title ID to the title stream. The client ID you use must have access to the title ID to successfully add them to the stream. This means the client ID you used to generate the token must have access to the title ID. You can only add title IDs to title level streams. Stream created using [createStream](0012.html#createstream) APIs are title level streams.

Events will be captured in the title stream only after adding Title IDs to the stream. If Title IDs are not added, then events related to those Title IDs will not be captured in the title stream.

After you created the stream using [createStream](0012.html#createstream) API and added Title IDs to the stream, please use [getStreamEventsV2](0012.html#getstreameventsv2) API to read events populated in the stream.

Adding a title ID only affects future events in the stream. Previous events are not added to the stream.

**Example: Add a title ID**

```
curl -X POST 'https://s2s.sp-int.playstation.net/api/partnerEventService/v1/partners/PARTNER1/streams/STREAM1/titles' -H "Authorization: Bearer {access_token}"
```

**Request:**

```
{"titleId":"ABCD12345_00"}
```

```
{
"status":"Success"
}
```
