# 内存横向对比与优化建议（三场景）

三场景 net-resident 内存对比 + 优化建议。数据 = 进程内 MemTrack dump（Total CPU / 池明细）+ WPR 内核 VirtualAlloc trace（net-resident，定位 GPU 后备 / 非池 heap 按函数）。场景：**长桥关卡（French Siege 战场）/ 大世界 / 登录页面**。

## 一、总 Commit 内存组成对比（找大头）

| 组成块 | 长桥关卡 | 大世界 | 登录页面 |
|---|---:|---:|---:|
| **Total CPU** | **19.9 GB** | **30.9 GB** | **7.76 GB** |
| ┈ mempool 内存池 | 6.06 | **18.68** | 2.27 |
| ┈ GPU 资源后备（D3D12 backing） | **8.49** | 5.73 | 0.91 |
| ┈ 非池 heap（直接 new/malloc/STL） | 2.64 | 3.05 | 2.18 |
| ┈ Image | 0.84 | 0.89 | 0.84 |
| ┈ MappedFile | 0.38 | 0.45 | 0.22 |
| ┈ Tracy（profiler） | 0.33 | 0.43 | 0.41 |

> **每场景最大头不同**：长桥（战场）= GPU 后备 8.49 GB；大世界 = mempool 18.68 GB（物理 8 GB + 兜底 5.48 GB + 网格 2.12 GB）；登录页面 = 固定开销基线（Wwise + CRT + RHIBuffer）。

## 三、非池 heap 对比（除了 mempool 的 heap 来自哪些函数）

走 CRT 堆但栈里无 mempool 帧的分配 = 直接 new/malloc/STL 绕过池。

| 来源 | 长桥 | 大世界 | 登录 | 性质 |
|---|---:|---:|---:|---|
| **非池 heap 总量** | **2,639** | **3,054** | **2,182** | |
| `AK::MemoryArena`（Wwise 自管 arena）| 1,422 | 1,424 | 1,173 | 第三方 SDK，固定 |
| ucrtbase `__crt_state_management`（CRT）| 614 | 633 | 610 | CRT runtime，固定 |
| NVIDIA 驱动堆（nvwgf2umx + nvapi64）| 248 | 415 | 140 | 驱动，无 PDB |
| dbghelp `pMemAlloc`（符号解析）| 70 | 72 | 71 | 工具/调试 |
| **chaos 业务**（Luau 脚本 + dtTileCache 导航）| 25 | 97 | 小 | **唯一的 chaos 直接 new/malloc** |

> **核心结论**：非池 heap 几乎全是第三方/系统库自管内存（Wwise ~1.2–1.4 GB 三场景恒定 + CRT ~0.6 GB 恒定 + 驱动 + dbghelp）。**chaos 业务代码绝大多数已走 mempool**，绕过池仅 Luau/dtTileCache 几十~百 MB。收编进 mempool 空间极小，要降得靠 Wwise 配置 / 关 dbghelp / 关 profiler。

## 四、GPU 资源后备趋势

全部走 d3d12core `D3DKMT_CREATEALLOCATION`（GPU 资源系统 RAM backing，驱动分配，CPU 池不可控）。

| 场景 | GPU 后备 | 占 Total CPU |
|---|---:|---:|
| 长桥关卡（战场） | 8.49 GB | 43% |
| 大世界 | 5.73 GB | 19% |
| 登录页面 | 0.91 GB | 12% |

> 战场态 GPU 驻留最重；大世界总量虽最高，GPU 后备反低（增量在 CPU 侧的物理/模型/地形）。

## 六、优化建议（按性价比）

1. **大世界物理**（PhysXPool + PhysicsPool 8 GB / `PhysXAllocator` 4.2 GB）：大世界最大可治项。→ HeightField 精度/分块、碰撞体 LOD、按距离卸载物理数据。
2. **Sketum 模型加载**（大世界 5.8 GB / 登录 0.6 GB）：→ 按需流送/卸载、共享重复网格、降常驻精度。
3. **Water/地形 QuadTree**（大世界 +2 GB，仅大世界）：→ QuadTree 按视距裁剪/分块。
4. **固定开销基线**（三场景恒定 ~2.7 GB）：Wwise arena 1.2–1.4 GB（最大杠杆，非池）+ CRT 0.6 GB + RHIBuffer 640 MB，连登录都常驻。→ 核对 Wwise arena 预分配配置、RHI buffer 初始容量。**全局降基线最容易的一块**。
5. **GPU 资源后备**（长桥 8.49 GB 最大）：驱动持有，池管不了。→ 与渲染团队做 GPU 资源数量/尺寸、纹理流送、驻留、upload heap 复用。
6. **细分 `PoolDefault`**（大世界 5.48 GB / 长桥 2.60 GB）：兜底池混杂。→ `setPoolDefaultCallerAttrib(true)` 跑一轮 → 拆独立池。
7. **非池 heap 收编空间已很小**：主体是第三方自管，chaos 业务绕过池仅 ~150 MB。→ 靠 Wwise 配置 / 关 dbghelp / 关 profiler，而非池化。
8. **关 Tracy/Optick + 排查 dbghelp**（~480–580 MB）：测量/正式构建关 profiler；dbghelp 非必要可延迟加载。

> **优先级**：大世界看 **物理 + 模型 + 地形**（CPU 内存主导）；长桥战场看 **GPU 资源后备**；全局看 **固定开销基线**（Wwise + CRT + RHIBuffer，所有场景受益）。chaos 业务已基本池化，剩细分 PoolDefault。
